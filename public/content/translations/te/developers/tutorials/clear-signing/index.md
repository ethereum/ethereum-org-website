చాలా ప్రధాన ఎథీరియం దోపిడీలు (exploits) ఒకే చివరి దశను కలిగి ఉన్నాయి: వినియోగదారుడు అర్థం చేసుకోలేని లావాదేవీని ఆమోదించడం. హార్డ్‌వేర్ వాలెట్‌లు ముడి హెక్స్ కాల్ డేటాను చూపుతాయి మరియు మరింత దారుణంగా బ్లైండ్ సంతకం చేయడాన్ని ఆన్ చేయమని మిమ్మల్ని బలవంతం చేస్తాయి. సాఫ్ట్‌వేర్ వాలెట్‌లు డీకోడ్ చేయబడిన ఫీల్డ్‌లను చూపుతాయి, కానీ అవి కాంట్రాక్ట్‌ను గుర్తించినప్పుడు మాత్రమే. ప్రోటోకాల్ కొత్తది కావడం వల్ల, యాప్ రాజీపడటం వల్ల లేదా పరికరం ఆఫ్‌లైన్‌లో ఉండటం వల్ల అవి గుర్తించనప్పుడు, వినియోగదారులు బ్లైండ్‌గా సంతకం చేస్తారు.

[ERC-7730](https://eips.ethereum.org/EIPS/eip-7730) మీ కాంట్రాక్ట్ ఫంక్షన్ కాల్‌ల *అర్థం* ఏమిటో వివరించడానికి ప్రామాణిక JSON ఫార్మాట్‌ను నిర్వచిస్తుంది.

ERC-7730కి మద్దతు ఇచ్చే వాలెట్ మీ డిస్క్రిప్టర్‌ను చదివి ఇలా చూపుతుంది:

> **మార్పిడి (Swap)**  
> పంపండి: 1,000 USDC  
> కనీసం స్వీకరించండి: 0.42 WETH  
> ప్రోటోకాల్: Uniswap V2

లేదా మానవులు మరియు ఏజెంట్లు ఇద్దరూ చదవగలిగే ఒకే వాక్యం:

> కనీసం 0.42 WETH కోసం 1,000 USDCని మార్పిడి చేయండి

ఫంక్షన్ సెలెక్టర్ మరియు ముడి పూర్ణాంక విలువల జాబితాకు బదులుగా.

ఇదే [స్పష్టమైన సంతకం చేయడం (clear signing)](https://clearsigning.org/) — "మీరు చూసేదే మీరు సంతకం చేసేది." ఈ ట్యుటోరియల్ మీ స్వంత కాంట్రాక్ట్ కోసం డిస్క్రిప్టర్‌ను వ్రాయడం, అధికారిక CLI సాధనంతో దాన్ని ధృవీకరించడం మరియు ఓపెన్ రిజిస్ట్రీకి సమర్పించడం ద్వారా మీకు మార్గనిర్దేశం చేస్తుంది.

## ముందస్తు అవసరాలు {#prerequisites}

- Solidity మరియు స్మార్ట్ కాంట్రాక్ట్ ABIల గురించి అవగాహన
- ధృవీకరించబడిన ABIతో డిప్లాయ్ చేయబడిన స్మార్ట్ కాంట్రాక్ట్ (డిస్క్రిప్టర్‌ను రిజిస్ట్రీకి ఆమోదించడానికి ముందు [Sourcify](https://sourcify.dev) ధృవీకరణ అవసరం)
- ధృవీకరణ CLI కోసం Python 3.12 (పిన్ చేయబడిన `erc7730` ప్యాకేజీ Python 3.13 లేదా ఆ తర్వాతి వెర్షన్‌లలో ఇన్‌స్టాల్ చేయబడదు). మీ సిస్టమ్ Python వేరే వెర్షన్ అయితే, [uv](https://docs.astral.sh/uv/) మీ కోసం Python 3.12ని డౌన్‌లోడ్ చేసి రన్ చేయగలదు
- ప్రాథమిక JSON పరిజ్ఞానం

## ERC-7730 డిస్క్రిప్టర్ అంటే ఏమిటి? {#what-is-an-erc-7730-descriptor}

డిస్క్రిప్టర్ అనేది మూడు విభాగాలతో కూడిన ఒకే JSON ఫైల్:

| విభాగం | ప్రయోజనం |
| :---- | :---- |
| `context` | చైన్ ID మరియు చిరునామా ద్వారా నిర్దిష్ట కాంట్రాక్ట్ డిప్లాయ్‌మెంట్‌లకు డిస్క్రిప్టర్‌ను బంధిస్తుంది |
| `metadata` | ప్రాజెక్ట్‌కు పేరు పెడుతుంది మరియు పునర్వినియోగ స్థిరాంకాలను నిర్వచిస్తుంది |
| `display` | ప్రతి ఫంక్షన్ సంతకాన్ని మానవులు చదవగలిగే లేబుల్‌లు మరియు ఫీల్డ్ ఫార్మాట్‌లకు మ్యాప్ చేస్తుంది |

డిస్క్రిప్టర్ కాంట్రాక్ట్ నుండి వేరుగా ఉన్నందున, మీరు మళ్లీ డిప్లాయ్ చేయకుండానే ఇప్పటికే ఉన్న ఏదైనా ప్రోటోకాల్‌కు స్పష్టమైన సంతకం చేసే మద్దతును జోడించవచ్చు. వాలెట్‌లు రిజిస్ట్రీ నుండి డిస్క్రిప్టర్‌లను తిరిగి పొందుతాయి మరియు సంతకం చేసే సమయంలో వాటిని ఉపయోగిస్తాయి.

## దశ 1: ఫైల్ స్కెలిటన్‌ను సృష్టించండి {#step-1-create-the-file-skeleton}

`calldata-<ContractName>.json` పేరుతో ఒక ఫైల్‌ను సృష్టించండి, ఉదాహరణకు `calldata-SwapRouter.json`. టైప్ చేయబడిన-డేటా సందేశాల కోసం `eip712-`కి విరుద్ధంగా, ఈ డిస్క్రిప్టర్ కాంట్రాక్ట్ ఫంక్షన్ కాల్‌లను కవర్ చేస్తుందని `calldata-` ప్రిఫిక్స్ రిజిస్ట్రీకి చెబుతుంది. మీరు కాంట్రాక్ట్ యొక్క అనేక వెర్షన్‌లను వివరించాల్సిన అవసరం ఉంటే, రిజిస్ట్రీ యొక్క `calldata-UniswapV3Router02.json`లో వలె పేరులో కాంట్రాక్ట్ వెర్షన్‌ను చేర్చండి.

```json
{
  "$schema": "https://eips.ethereum.org/assets/eip-7730/erc7730-v2.schema.json",
  "context": {},
  "metadata": {},
  "display": {
    "formats": {}
  }
}
```

## దశ 2: సందర్భ విభాగాన్ని వ్రాయండి {#step-2-write-the-context-section}

`context` విభాగం డిస్క్రిప్టర్‌ను ఒకటి లేదా అంతకంటే ఎక్కువ కాంట్రాక్ట్ డిప్లాయ్‌మెంట్‌లకు బంధిస్తుంది. ఇన్‌కమింగ్ లావాదేవీని సరైన డిస్క్రిప్టర్‌తో సరిపోల్చడానికి వాలెట్‌లు దీన్ని ఉపయోగిస్తాయి.

```json
"context": {
  "$id": "example-swap-router",
  "contract": {
    "deployments": [
      { "chainId": 1, "address": "0xYourContractAddressOnMainnet" },
      { "chainId": 137, "address": "0xYourContractAddressOnPolygon" }
    ]
  }
}
```

### సందర్భ ఫీల్డ్‌లు {#context-fields}

- `context.$id` — ఈ డిస్క్రిప్టర్ డాక్యుమెంట్ లేదా డిప్లాయ్‌మెంట్ కాన్ఫిగరేషన్ కోసం ఒక ప్రత్యేక ఐడెంటిఫైయర్.
- `contract.deployments` — ఈ డిస్క్రిప్టర్ వర్తించే డిప్లాయ్‌మెంట్‌ల సెట్.
- `deployments[].chainId` — డిప్లాయ్‌మెంట్ కోసం EVM చైన్ ID. మీ కాంట్రాక్ట్ డిప్లాయ్ చేయబడిన ప్రతి చైన్‌ను చేర్చండి.
- `deployments[].address` — వాలెట్‌లు ఈ డిస్క్రిప్టర్‌తో అనుబంధించాల్సిన కాంట్రాక్ట్ చిరునామా. వినియోగదారులు వాస్తవానికి లావాదేవీలను పంపే చిరునామా ఇది. మీ కాంట్రాక్ట్ అప్‌గ్రేడ్ చేయదగినది అయితే, అది ప్రాక్సీ చిరునామా, ఇంప్లిమెంటేషన్ చిరునామా కాదు, అయితే `display.formats`లోని ఫంక్షన్ సంతకాలు ఇంప్లిమెంటేషన్ యొక్క ABI నుండి వస్తాయి.

## దశ 3: మెటాడేటా విభాగాన్ని వ్రాయండి {#step-3-write-the-metadata-section}

మెటాడేటా విభాగం ఈ ఫైల్ ద్వారా వివరించబడిన ప్రాజెక్ట్ మరియు కాంట్రాక్ట్ గురించి మానవులు చదవగలిగే సమాచారాన్ని అందిస్తుంది. సంతకం చేసే సమయంలో ప్రోటోకాల్ పేర్లు, లింక్‌లు మరియు ఇతర సందర్భోచిత వివరాలను ప్రదర్శించడానికి వాలెట్‌లు ఈ సమాచారాన్ని ఉపయోగించవచ్చు.

```json
"metadata": {
  "owner": "Example Swap Protocol",
  "info": { "url": "https://example.xyz" },
  "contractName": "SwapRouter"
}
```

### మెటాడేటా ఫీల్డ్‌లు {#metadata-fields}

- `owner` — ఈ డిస్క్రిప్టర్‌కు బాధ్యత వహించే ప్రాజెక్ట్, ప్రోటోకాల్, సంస్థ లేదా నిర్వహించేవారు.
- `info.url` — అదనపు సందర్భం కోసం వాలెట్‌లు వినియోగదారులకు ప్రదర్శించగల కానానికల్ ప్రాజెక్ట్ లేదా డాక్యుమెంటేషన్ URL.
- `contractName` — ఈ ఫైల్ ద్వారా వివరించబడిన కాంట్రాక్ట్ లేదా ఇంప్లిమెంటేషన్ పేరు, సాధారణంగా ధృవీకరించబడిన సోర్స్ కోడ్ లేదా ABIతో సరిపోలుతుంది.

మీ ERC-7730 ఫైల్ ERC-20 కాంట్రాక్ట్‌ను వివరిస్తే, మీరు టోకెన్ ఆబ్జెక్ట్‌ను కూడా జోడించాలి. 

## దశ 4: ప్రదర్శన ఫార్మాట్‌ల విభాగాన్ని వ్రాయండి {#step-4-write-the-displayformats-section}

`display.formats` ఆబ్జెక్ట్ ఫంక్షన్ సంతకాలను మానవులు చదవగలిగే సంతకం సూచనలకు మ్యాప్ చేస్తుంది. వినియోగదారులు లావాదేవీని ఆమోదించడానికి ముందు వాలెట్‌లు మీ ఫంక్షన్‌ను వారికి ఈ విధంగా చూపుతాయి!

ప్రతి కీ మానవులు చదవగలిగే ABI ఫ్రాగ్‌మెంట్ — మీ ABIలో కనిపించే విధంగానే పారామీటర్ పేర్లు మరియు పారామీటర్ రకాలు రెండింటినీ కలిగి ఉన్న ఫంక్షన్ సంతకం.


### ఉదాహరణ: టోకెన్ మార్పిడిని వివరించడం {#eg-describing-token-swap}

ఈ ఉదాహరణ Uniswap V2 `Router02` కాంట్రాక్ట్ నుండి `swapExactTokensForTokens`ని వివరిస్తుంది. ఇన్‌పుట్ టోకెన్ అనేది `path` యొక్క మొదటి మూలకం, మరియు అవుట్‌పుట్ టోకెన్ చివరిది (మల్టీ-హాప్ మార్పిడి కోసం `path` రెండు కంటే ఎక్కువ మూలకాలను కలిగి ఉండవచ్చు).

```json
"display": {
  "formats": {
    "swapExactTokensForTokens(uint256 amountIn,uint256 amountOutMin,address[] path,address to,uint256 deadline)": {
      "intent": "Swap",
      "interpolatedIntent": "Swap {amountIn} for at least {amountOutMin}",
      "fields": [
        {
```

### ప్రదర్శన ఫీల్డ్‌లు {#display-fields}

- **`intent`** — **(అవసరం)** "మార్పిడి (Swap)" వంటి చర్య యొక్క చిన్న, వినియోగదారు-స్నేహపూర్వక వివరణ.
- **`interpolatedIntent`** — **(సిఫార్సు చేయబడింది)** `"Swap {amountIn} for at least {amountOutMin}"` వంటి ఫార్మాట్ చేయబడిన ఫీల్డ్ విలువలను పొందుపరిచే మరింత మెరుగైన వాక్య టెంప్లేట్. ఏవైనా ప్రదర్శన పరిమితులు ఉన్నట్లయితే వాలెట్‌లు చూపించడానికి ఎంచుకోగల మరింత వినియోగదారు స్నేహపూర్వక డిస్క్రిప్టర్‌ను అందించడానికి `intent`తో పాటు దీన్ని చేర్చండి.
- **`fields`** — **(అవసరం)** వాలెట్‌లు వినియోగదారులకు ప్రదర్శించాల్సిన లావాదేవీ ఫీల్డ్‌ల ఆర్డర్ చేయబడిన జాబితా.
  - **`path`** — **(అవసరం)** లావాదేవీ డేటాకు సూచన. `#.fieldName` అనేది ABIలోని పేరు ద్వారా డీకోడ్ చేయబడిన కాల్ డేటా పారామీటర్‌ను సూచిస్తుంది. `@.value` లావాదేవీతో పంపబడిన ETH విలువను సూచిస్తుంది. శ్రేణి (Array) మూలకాలు బ్రాకెట్‌లకు ముందు `.`తో వ్రాయబడతాయి: `#.path.[0]` మొదటి మూలకం మరియు `#.path.[-1]` చివరిది. `#.path[0]` (చుక్క లేకుండా) లింటర్ ద్వారా తిరస్కరించబడుతుంది.
  - **`label`** — **(అవసరం)** విలువ పక్కన చూపబడే మానవులు చదవగలిగే లేబుల్.
  - **`format`** — **(సిఫార్సు చేయబడింది)** విలువ ఎలా రెండర్ చేయబడాలో నియంత్రిస్తుంది. సాధారణ ఫార్మాట్‌లు:
    - `tokenAmount`
    - `addressName`
    - `date`

    అదనపు ఫార్మాటింగ్ అవసరం లేనప్పుడు `raw`ని ఉపయోగించండి. కొన్ని ఫార్మాట్‌లు అదనపు **`params`** కాన్ఫిగరేషన్‌ను అంగీకరిస్తాయి. ఉదాహరణకు:

    - ఏ టోకెన్ చిరునామా దశాంశాలు మరియు టిక్కర్ మెటాడేటాను అందిస్తుందో గుర్తించడానికి `tokenAmount` `tokenPath`ని ఉపయోగించవచ్చు.
    - టైమ్‌స్టాంప్ ఎలా ఎన్‌కోడ్ చేయబడిందో వివరించడానికి `date` `encoding`ని ఉపయోగించవచ్చు.

    ఎంచుకున్న ఫార్మాట్‌కు అదనపు సమాచారం అవసరం లేకపోతే, `params`ని వదిలివేయండి.

## దశ 5: రిజిస్ట్రీకి సమర్పించండి {#step-5-submit-to-the-registry}

[ERC-7730 రిజిస్ట్రీ](https://github.com/ethereum/clear-signing-erc7730-registry) అనేది తటస్థ స్టీవార్డ్‌గా [ఎథీరియం ఫౌండేషన్](/foundation/) ద్వారా హోస్ట్ చేయబడిన ఓపెన్ రిపోజిటరీ. ఎవరైనా దీన్ని క్లోన్ చేయడానికి మరియు స్వీయ-హోస్ట్ చేయడానికి స్వేచ్ఛగా ఉన్నారు — వాలెట్‌లు ఏ రిజిస్ట్రీ ఇన్‌స్టాన్స్‌లను విశ్వసిస్తాయో స్వతంత్రంగా నిర్ణయిస్తాయి.

1. GitHubలో రిపోజిటరీని ఫోర్క్ చేయండి
2. `registry/<your-project-name>/` వద్ద ఫోల్డర్‌ను సృష్టించండి
3. మీ ఫైల్‌ను దాని లోపల ఉంచండి: `registry/myproject/calldata-SwapRouter.json`
4. రెపోలో ఉపయోగించిన సాపేక్ష మార్గానికి `$schema` ఫీల్డ్‌ను అప్‌డేట్ చేయండి: `"../../specs/erc7730-v2.schema.json"`. CI ఇక్కడ URLని తిరస్కరిస్తుంది.
5. పరీక్ష ఫైల్‌ను జోడించండి (క్రింద చూడండి)
6. మీ ఫైల్‌లను స్థానికంగా ధృవీకరించండి (క్రింద చూడండి)
7. పుల్ రిక్వెస్ట్‌ను తెరవండి. ప్రతి పుల్ రిక్వెస్ట్ `registry/` కింద ఒక ఫోల్డర్‌ను మాత్రమే మార్చగలదు

### పరీక్ష ఫైల్‌ను జోడించండి {#add-a-test-file}

మీరు జోడించే లేదా మార్చే ప్రతి డిస్క్రిప్టర్‌కు పరీక్ష ఫైల్ అవసరం, కాబట్టి స్పష్టమైన సంతకం చేసే ఇంప్లిమెంటేషన్‌లను దానికి వ్యతిరేకంగా తనిఖీ చేయవచ్చు. `display.formats`లోని ప్రతి ఫంక్షన్ కోసం కనీసం ఒక పరీక్ష కేసుతో `registry/<your-project-name>/testsv2/calldata-<ContractName>.tests.json`ని సృష్టించండి. CI ప్రతి ఫార్మాట్ యొక్క ఫంక్షన్ సెలెక్టర్‌ను పొందుతుంది మరియు ఏ పరీక్ష లావాదేవీ దాన్ని కాల్ చేయకపోతే విఫలమవుతుంది.

```json
{
  "$schema": "../../../specs/erc7730-tests-v2.schema.json",
  "descriptor": "../calldata-SwapRouter.json",
  "dataProvider": {
    "tokens": {
      "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48": { "symbol": "USDC", "decimals": 6, "name": "USD Coin" },
      "0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2": { "symbol": "WETH", "decimals": 18, "name": "Wrapped Ether" }
    }
  },
  "tests": [
    {
      "description": "Swap 1,000 USDC for at least 0.42 WETH",
      "rawTx": "0x02f9012f0180843b9aca00...",
      "expected": {
        "intent": "Swap",
        "interpolatedIntent": "Swap 1000 USDC for at least 0.42 WETH",
        "owner": "Example Swap Protocol",
        "fields": [
          { "label": "Send", "value": "1000 USDC" },
          { "label": "Receive minimum", "value": "0.42 WETH" },
          { "label": "Recipient", "value": "0x1234567890123456789012345678901234567890" },
          { "label": "Expires", "value": "2026-01-01 00:00:00Z" }
        ]
      }
    }
  ]
}
```

- `rawTx` అనేది కాల్ డేటా మాత్రమే కాకుండా, పూర్తి సీరియలైజ్ చేయబడిన **సంతకం చేయని** లావాదేవీ (ఇక్కడ కుదించబడింది). మీ కాంట్రాక్ట్‌కు నిజమైన లావాదేవీలు ఉత్తమ పరీక్ష కేసులు.
- `dataProvider` టోకెన్ మెటాడేటాను (మరియు ఐచ్ఛికంగా చిరునామా మరియు ENS పేర్లను) సరఫరా చేస్తుంది కాబట్టి పరీక్షలకు నెట్‌వర్క్ యాక్సెస్ అవసరం లేదు.
- `expected` అనేది వాలెట్ ప్రదర్శించాల్సినది. CI ప్రతి పరీక్ష కేసును స్పష్టమైన సంతకం చేసే ఇంప్లిమెంటేషన్‌లతో రెండర్ చేస్తుంది మరియు పుల్ రిక్వెస్ట్‌పై ఏవైనా తేడాలను నివేదిస్తుంది.

EIP-712 డిస్క్రిప్టర్‌ల కోసం పరీక్ష ఫైల్‌లతో సహా పూర్తి ఫార్మాట్ కోసం రిజిస్ట్రీ READMEలోని [రిఫరెన్స్ పరీక్ష కేసులు](https://github.com/ethereum/clear-signing-erc7730-registry#reference-test-cases) చూడండి.

### స్థానికంగా ధృవీకరించండి {#validate-locally}

రిజిస్ట్రీ `.github/requirements.txt`లో పిన్ చేయబడిన [`erc7730`](https://github.com/sourcifyeth/python-erc7730) కమాండ్-లైన్ సాధనంతో డిస్క్రిప్టర్‌లను తనిఖీ చేస్తుంది. Python 3.12 వాతావరణంలో మీ ఫోర్క్ యొక్క రూట్ నుండి దీన్ని రన్ చేయండి:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r .github/requirements.txt
erc7730 lint registry/myproject/calldata-SwapRouter.json
```

మీరు [uv](https://docs.astral.sh/uv/)ని ఉపయోగిస్తే, మీరు వర్చువల్ వాతావరణాన్ని దాటవేయవచ్చు మరియు అవసరమైతే uv Python 3.12ని డౌన్‌లోడ్ చేస్తుంది:

```sh
uvx --python 3.12 --from "$(cat .github/requirements.txt)" erc7730 lint registry/myproject/calldata-SwapRouter.json
```

లింటర్ స్కీమాకు వ్యతిరేకంగా మరియు మీ కాంట్రాక్ట్ యొక్క ధృవీకరించబడిన ABIకి వ్యతిరేకంగా డిస్క్రిప్టర్‌ను తనిఖీ చేస్తుంది. ప్రతి లోపాన్ని పరిష్కరించండి. `Missing display format` వంటి హెచ్చరికలు అంటే మీ డిస్క్రిప్టర్ ఇంకా వివరించని ఫంక్షన్‌లను కాంట్రాక్ట్ కలిగి ఉందని అర్థం. CI చేసే విధంగా `$schema` మార్గాలను మరియు పరీక్ష ఫైల్‌ను కూడా తనిఖీ చేయడానికి, రిజిస్ట్రీ READMEలోని [ఎలా ధృవీకరించాలి](https://github.com/ethereum/clear-signing-erc7730-registry#how-to-validate) చూడండి.

మీరు PRని తెరిచినప్పుడు, CI స్వయంచాలకంగా స్కీమా ధృవీకరణను రన్ చేస్తుంది, ఫంక్షన్ సంతకాలు చెల్లుబాటు అయ్యే సెలెక్టర్‌లను ఉత్పత్తి చేస్తాయో లేదో తనిఖీ చేస్తుంది, కాంట్రాక్ట్ చిరునామా Sourcifyలో ధృవీకరించబడిందని నిర్ధారిస్తుంది మరియు ABI అసమానతలను ఫ్లాగ్ చేస్తుంది. తనిఖీ ఫలితాలు PRలో ఇన్‌లైన్‌లో కనిపిస్తాయి. రిజిస్ట్రీ మెయింటెయినర్లు తప్పుగా ఉన్న లేదా హానికరమైన డిస్క్రిప్టర్‌ల కోసం సమర్పణలను స్క్రీన్ చేస్తారు. రిజిస్ట్రీలో చేర్చడం అనేది ఆడిట్ లేదా ఆమోదాన్ని సూచించదు.

## విలీనం చేసిన తర్వాత ఏమి జరుగుతుంది? {#what-happens-after-merging}

రిజిస్ట్రీలోని అన్ని డిస్క్రిప్టర్‌లు ఆడిటర్‌లకు అందుబాటులో ఉంటాయి. మీ PR విలీనం చేయబడిన తర్వాత, ఏ ఆడిటర్ అయినా మీ డిస్క్రిప్టర్‌ను సమీక్షించవచ్చు మరియు దాని ఖచ్చితత్వాన్ని నిర్ధారిస్తూ క్రిప్టోగ్రాఫిక్ ధృవీకరణను ([ERC-8176](https://eips.ethereum.org/EIPS/eip-8176) కింద) ప్రచురించవచ్చు. 

ఈ ధృవీకరణ సంకేతాలు వాలెట్‌లు తమ స్వంత విశ్వాస విధానాలను వర్తింపజేయడానికి అనుమతిస్తాయి — బహుళ స్వతంత్ర ధృవీకరణలు ఉన్న డిస్క్రిప్టర్ లేని దానికంటే ఎక్కువ బరువును కలిగి ఉంటుంది. మీరు [clearsigning.org](https://clearsigning.org) ద్వారా ఆడిటర్ కమ్యూనిటీని చేరుకోవచ్చు.

వాలెట్‌లు తాము ఏ రిజిస్ట్రీకి మద్దతు ఇస్తాయో ఎంచుకుంటాయి. మీ డిస్క్రిప్టర్ రిజిస్ట్రీలో ఉన్న తర్వాత, ERC-7730కి మద్దతు ఇచ్చే వాలెట్‌లు అది వాటి రిజిస్ట్రీలో ఉంటే దాన్ని పొందడం ప్రారంభిస్తాయి మరియు వినియోగదారులు మీ కాంట్రాక్ట్‌తో ఇంటరాక్ట్ అయినప్పుడు మానవులు చదవగలిగే డేటాను ప్రదర్శిస్తాయి.
