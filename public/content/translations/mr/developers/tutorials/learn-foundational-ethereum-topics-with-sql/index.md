अनेक इथेरियम ट्युटोरिअल्स डेव्हलपर्सना लक्ष्य करतात, परंतु डेटा विश्लेषकांसाठी किंवा क्लायंट किंवा नोड न चालवता ऑनचेन डेटा पाहू इच्छिणाऱ्या लोकांसाठी शैक्षणिक संसाधनांची कमतरता आहे.

हे ट्युटोरिअल वाचकांना [Dune](https://dune.com/) द्वारे प्रदान केलेल्या इंटरफेसद्वारे स्ट्रक्चर्ड क्वेरी लँग्वेज (SQL) सह ऑनचेन डेटा क्वेरी करून व्यवहार, ब्लॉक्स आणि गॅस यांसारख्या मूलभूत इथेरियम संकल्पना समजून घेण्यास मदत करते. या क्वेरीज [DuneSQL](https://docs.dune.com/query-engine/overview) वापरतात, जी Dune ची SQL बोली आहे.

ऑनचेन डेटा आपल्याला इथेरियम, नेटवर्क आणि संगणकीय शक्तीसाठी एक अर्थव्यवस्था म्हणून समजून घेण्यास मदत करू शकतो आणि आज इथेरियमसमोरील आव्हाने (उदा. वाढत्या गॅस किमती) आणि त्याहूनही महत्त्वाचे म्हणजे, स्केलिंग सोल्यूशन्सच्या आसपासच्या चर्चा समजून घेण्यासाठी एक आधार म्हणून काम केले पाहिजे.

### व्यवहार {#transactions}

इथेरियमवरील वापरकर्त्याचा प्रवास वापरकर्ता-नियंत्रित खाते किंवा ETH शिल्लक असलेल्या घटकास प्रारंभ करण्यापासून सुरू होतो. खात्याचे दोन प्रकार आहेत - वापरकर्ता-नियंत्रित किंवा स्मार्ट कॉन्ट्रॅक्ट (पहा [ethereum.org](/developers/docs/accounts/)).

कोणतेही खाते [Etherscan](https://etherscan.io/) किंवा [Blockscout](https://eth.blockscout.com/) सारख्या ब्लॉक एक्सप्लोररवर पाहिले जाऊ शकते. ब्लॉक एक्सप्लोरर हे इथेरियमच्या डेटाचे पोर्टल आहेत. ते रिअल-टाइममध्ये ब्लॉक्स, व्यवहार, प्रमाणक, खाती आणि इतर ऑनचेन क्रियाकलापांवरील डेटा प्रदर्शित करतात ([येथे](/developers/docs/data-and-analytics/block-explorers/) पहा).

तथापि, बाह्य ब्लॉक एक्सप्लोरर्सद्वारे प्रदान केलेल्या माहितीचा मेळ घालण्यासाठी वापरकर्त्याला थेट डेटा क्वेरी करण्याची इच्छा असू शकते. [Dune](https://dune.com/) SQL चे थोडे ज्ञान असलेल्या कोणालाही ही क्षमता प्रदान करते.

संदर्भासाठी, इथेरियम फाउंडेशन (EF) चे स्मार्ट कॉन्ट्रॅक्ट खाते [Blockscout](https://eth.blockscout.com/address/0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe) वर पाहिले जाऊ शकते.

एक गोष्ट लक्षात घेण्यासारखी आहे की EF च्या खात्यासह सर्व खात्यांचा एक सार्वजनिक पत्ता असतो जो व्यवहार पाठवण्यासाठी आणि प्राप्त करण्यासाठी वापरला जाऊ शकतो.

Etherscan वरील खात्यातील शिल्लक नियमित व्यवहार आणि अंतर्गत व्यवहारांनी बनलेली असते. अंतर्गत व्यवहार, नावाप्रमाणेच, चेनची स्थिती बदलणारे _प्रत्यक्ष_ व्यवहार नसतात. ते कॉन्ट्रॅक्ट कार्यान्वित करून सुरू केलेले मूल्य हस्तांतरण आहेत ([स्रोत](https://ethereum.stackexchange.com/questions/3417/how-to-get-contract-internal-transactions)). अंतर्गत व्यवहारांवर कोणतीही स्वाक्षरी नसल्यामुळे, त्यांचा ब्लॉकचेनवर व्यवहार म्हणून समावेश केला जात **नाही**. Dune त्यांची `ethereum.traces` टेबलमध्ये स्वतंत्रपणे नोंद करते.

म्हणून, हे ट्युटोरिअल नियमित व्यवहारांवर लक्ष केंद्रित करेल. हे अशा प्रकारे क्वेरी केले जाऊ शकते:

```sql
WITH temp_table AS (
SELECT
    hash,
    block_number,
    block_time,
    "from",
    "to",
    value / 1e18 AS ether,
    gas_used,
    gas_price / 1e9 AS gas_price_gwei
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
)
SELECT
    hash,
    block_number,
    block_time,
    "from",
    "to",
    ether,
    (gas_used * gas_price_gwei) / 1e9 AS txn_fee
FROM temp_table
```

लक्षात घ्या की पत्ते अवतरण चिन्हांशिवाय `0x...` लिटरल्स म्हणून लिहिले जातात. DuneSQL मध्ये, पत्ते आणि हॅश हे बायनरी मूल्ये आहेत, स्ट्रिंग्स नाहीत.

हे Etherscan च्या व्यवहार पृष्ठावर प्रदान केलेल्या माहितीसारखीच माहिती देईल. तुलनेसाठी, येथे दोन स्रोत आहेत:

### व्यवहारांचे विश्लेषण {#breaking-down-transactions}

सबमिट केलेल्या व्यवहारामध्ये अनेक माहिती समाविष्ट असते, ज्यामध्ये खालील गोष्टींचा समावेश आहे ([स्रोत](/developers/docs/transactions/)):

- **प्राप्तकर्ता**: प्राप्त करणारा पत्ता ("to" म्हणून क्वेरी केलेला)
- **स्वाक्षरी**: प्रेषकाची खाजगी की व्यवहारावर स्वाक्षरी करत असली तरी, आपण SQL सह प्रेषकाचा सार्वजनिक पत्ता ("from") क्वेरी करू शकतो.
- **मूल्य**: ही हस्तांतरित केलेली ETH ची रक्कम आहे (`ether` कॉलम पहा).
- **डेटा**: हा अनियंत्रित डेटा आहे जो हॅश केला गेला आहे (`data` कॉलम पहा)
- **gasLimit** – व्यवहाराद्वारे वापरल्या जाणाऱ्या गॅस युनिट्सची कमाल रक्कम. गॅसचे युनिट्स संगणकीय पायऱ्या दर्शवतात
- **maxPriorityFeePerGas** - प्रमाणकाला टिप म्हणून समाविष्ट करण्यासाठी गॅसची कमाल रक्कम
- **maxFeePerGas** - व्यवहारासाठी भरण्यास तयार असलेली गॅसची कमाल रक्कम (baseFeePerGas आणि maxPriorityFeePerGas सह)

आपण इथेरियम फाउंडेशनच्या सार्वजनिक पत्त्यावरील व्यवहारांसाठी या विशिष्ट माहितीची क्वेरी करू शकतो:

```sql
SELECT
    "to",
    "from",
    value / 1e18 AS ether,
    data,
    gas_limit,
    gas_price / 1e9 AS gas_price_gwei,
    gas_used,
    ROUND(CAST(gas_used AS DOUBLE) / gas_limit * 100, 2) AS gas_used_pct
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
```

`CAST` आवश्यक आहे कारण DuneSQL मध्ये एका पूर्णांकाला दुसऱ्याने भागल्यास पूर्णांक परिणाम मिळतो, ज्यामुळे जवळजवळ प्रत्येक टक्केवारी शून्यावर राऊंड डाउन होईल.

### ब्लॉक्स {#blocks}

प्रत्येक व्यवहार इथरियम व्हर्च्युअल मशीन (EVM) ची स्थिती बदलेल ([EVM](/developers/docs/evm/)) ([स्रोत](/developers/docs/transactions/)). व्यवहार सत्यापित करण्यासाठी आणि ब्लॉक मध्ये समाविष्ट करण्यासाठी नेटवर्कवर प्रसारित केले जातात. प्रत्येक व्यवहार ब्लॉक क्रमांकाशी संबंधित असतो. डेटा पाहण्यासाठी, आपण विशिष्ट ब्लॉक क्रमांकाची क्वेरी करू शकतो: 12396854 (मे 2021 मध्ये लिहिताना इथेरियम फाउंडेशनच्या व्यवहारांमधील सर्वात अलीकडील ब्लॉक).

शिवाय, जेव्हा आपण पुढील दोन ब्लॉक्सची क्वेरी करतो, तेव्हा आपण पाहू शकतो की प्रत्येक ब्लॉकमध्ये मागील ब्लॉकचा हॅश (म्हणजेच, मूळ हॅश) असतो, जे ब्लॉकचेन कशी तयार होते हे स्पष्ट करते.

प्रत्येक ब्लॉकमध्ये त्याच्या मूळ ब्लॉकचा संदर्भ असतो. हे खाली `hash` आणि `parent_hash` कॉलम्स दरम्यान दर्शविले आहे ([स्रोत](/developers/docs/blocks/)):

![parent_hash](./parent_hash.png)

येथे क्वेरी आहे:

```sql
SELECT
   time,
   number,
   hash,
   parent_hash,
   nonce
FROM ethereum.blocks
WHERE number IN (12396854, 12396855, 12396856)
```

आपण वेळ, ब्लॉक क्रमांक, हॅश, मूळ हॅश आणि नॉन्स क्वेरी करून ब्लॉक तपासू शकतो. ब्लॉक 12396854 [द मर्ज](/roadmap/merge/) पूर्वी तयार केला गेला होता, जेव्हा ब्लॉक्स प्रूफ-ऑफ-वर्क (PoW) सह माइन केले गेले होते आणि नॉन्स अर्थपूर्ण होता. प्रूफ-ऑफ-स्टेक (PoS) ब्लॉक्समध्ये नॉन्स नेहमी शून्य असतो.

या क्वेरीमध्ये समाविष्ट नसलेली एकमेव गोष्ट म्हणजे _व्यवहारांची यादी_ ज्यासाठी खाली स्वतंत्र क्वेरी आवश्यक आहे आणि _स्थिती मूळ (state root)_. पूर्ण किंवा आर्काइव्हल नोड सर्व व्यवहार आणि स्थिती संक्रमणे संग्रहित करेल, ज्यामुळे क्लायंट्सना कोणत्याही वेळी चेनच्या स्थितीची क्वेरी करण्याची अनुमती मिळते. यासाठी मोठ्या स्टोरेज स्पेसची आवश्यकता असल्यामुळे, आपण चेन डेटाला स्थिती डेटापासून वेगळे करू शकतो:

- चेन डेटा (ब्लॉक्स, व्यवहारांची यादी)
- स्थिती डेटा (प्रत्येक व्यवहाराच्या स्थिती संक्रमणाचा परिणाम)

स्थिती मूळ (state root) नंतरच्या श्रेणीत येते आणि तो _अव्यक्त (implicit)_ डेटा आहे (ऑनचेन संग्रहित केलेला नाही), तर चेन डेटा स्पष्ट आहे आणि चेनवरच संग्रहित केला जातो ([स्रोत](https://ethereum.stackexchange.com/questions/359/where-is-the-state-data-stored)).

या ट्युटोरिअलसाठी, आपण ऑनचेन डेटावर लक्ष केंद्रित करू जो Dune द्वारे SQL सह क्वेरी केला जाऊ _शकतो_.

वर नमूद केल्याप्रमाणे, प्रत्येक ब्लॉकमध्ये व्यवहारांची यादी असते, आपण विशिष्ट ब्लॉकसाठी फिल्टर करून याची क्वेरी करू शकतो. आपण ब्लॉक 12396854 वापरून पाहू:

```sql
SELECT * FROM ethereum.transactions
WHERE block_number = 12396854
```

Dune वरील SQL आउटपुट येथे आहे:

![Screenshot of a list of Ethereum transactions](./list_of_txn.png)

चेनमध्ये जोडला जाणारा हा एकच ब्लॉक इथरियम व्हर्च्युअल मशीन (EVM) ची स्थिती बदलतो ([EVM](/developers/docs/evm/)). डझनभर, कधीकधी शेकडो व्यवहार एकाच वेळी सत्यापित केले जातात. या विशिष्ट प्रकरणात, 222 व्यवहार समाविष्ट केले गेले.

प्रत्यक्षात किती यशस्वी झाले हे पाहण्यासाठी, आपण यशस्वी व्यवहार मोजण्यासाठी आणखी एक फिल्टर जोडू:

```sql
SELECT
    COUNT(*) AS num_successful_txn
FROM ethereum.transactions
WHERE block_number = 12396854 AND success = true
```

ब्लॉक 12396854 साठी, एकूण 222 व्यवहारांपैकी, 204 यशस्वीरित्या सत्यापित केले गेले:

![Screenshot of a successful Ethereum transaction](./successful_txn.png)

व्यवहाराच्या विनंत्या प्रति सेकंद डझनभर वेळा येतात, परंतु ब्लॉक्स केवळ ठराविक काळाने जोडले जातात ([स्रोत](/developers/docs/blocks/)). प्रूफ-ऑफ-वर्क अंतर्गत, खूप फरकासह, सरासरी दर 13 ते 15 सेकंदांनी एक ब्लॉक माइन केला जात असे. सप्टेंबर 2022 मध्ये [द मर्ज](/roadmap/merge/) झाल्यापासून, प्रूफ-ऑफ-स्टेक वेळेला 12 सेकंदांच्या स्लॉटमध्ये विभागते आणि प्रत्येक स्लॉटमध्ये जास्तीत जास्त एक ब्लॉक असू शकतो.

त्यामुळे आज दररोज जास्तीत जास्त 86400 / 12 = 7200 ब्लॉक्स असू शकतात. व्यवहारात ते थोडे कमी असतात, कारण एखादा प्रमाणक कधीकधी त्याचा स्लॉट चुकवतो.

दररोज तयार होणाऱ्या इथेरियम ब्लॉक्सचा चार्ट (2016 - 2021) असा आहे:

![Chart showing daily Ethereum block production](./daily_blocks.png)

या कालावधीत दररोज तयार होणाऱ्या ब्लॉक्सची सरासरी संख्या ~5,874 आहे:

![Chart showing daily Ethereum block production](./avg_daily_blocks.png)

क्वेरीज खालीलप्रमाणे आहेत:

दररोज तयार होणाऱ्या ब्लॉक्सची संख्या पाहण्यासाठी येथे क्वेरी आहे. `WHERE` क्लॉज चालू दिवस वगळतो, जो अद्याप संपलेला नाही.

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    COUNT(*) AS block_count
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

आणि ही क्वेरी द मर्जच्या आधी आणि नंतर दररोज तयार होणाऱ्या ब्लॉक्सच्या सरासरी संख्येची गणना करते. ब्लॉक 15537394 हा पहिला प्रूफ-ऑफ-स्टेक ब्लॉक आहे.

```sql
WITH daily AS (
    SELECT
        DATE_TRUNC('day', time) AS dt,
        MIN(number) >= 15537394 AS after_merge,
        COUNT(*) AS block_count
    FROM ethereum.blocks
    WHERE time < DATE_TRUNC('day', NOW())
    GROUP BY 1
)
SELECT
    after_merge,
    AVG(block_count) AS avg_block_count,
    86400 / AVG(block_count) AS avg_seconds_per_block
FROM daily
GROUP BY 1
```

जेव्हा हे ट्युटोरिअल पहिल्यांदा मे 2021 मध्ये लिहिले गेले होते, तेव्हा सरासरी दररोज 5,874 ब्लॉक्स किंवा दर 14.7 सेकंदाला एक ब्लॉक होती. द मर्ज नंतर, सरासरी 7200 च्या कमाल मर्यादेच्या अगदी खाली आहे, सुमारे दर 12 सेकंदाला एक ब्लॉक.

### गॅस {#gas}

ब्लॉक्स आकारात मर्यादित असतात. प्रत्येक ब्लॉकची गॅस मर्यादा असते आणि [EIP-1559](/developers/docs/gas/#base-fee) पासून प्रत्येक ब्लॉकचे गॅस लक्ष्य देखील असते, जे मर्यादेच्या निम्मे असते. जेव्हा ब्लॉक्स लक्ष्यापेक्षा जास्त गॅस वापरतात, तेव्हा पायाभूत शुल्क वाढते आणि जेव्हा ते कमी वापरतात, तेव्हा ते कमी होते. गॅस मर्यादा स्वतः प्रमाणकांद्वारे समायोजित केली जाते आणि ती गेल्या काही वर्षांत अनेक वेळा वाढवली गेली आहे. डिस्क स्पेस आणि गती आवश्यकतांच्या बाबतीत पूर्ण नोड्सवर ताण आणणाऱ्या अनियंत्रितपणे मोठ्या ब्लॉक आकारांना प्रतिबंधित करण्यासाठी मर्यादा आवश्यक आहेत ([स्रोत](/developers/docs/blocks/)).

ब्लॉक गॅस मर्यादेची संकल्पना करण्याचा एक मार्ग म्हणजे त्याचा विचार उपलब्ध ब्लॉक स्पेसचा **पुरवठा** म्हणून करणे ज्यामध्ये व्यवहारांची बॅच केली जाते. ब्लॉक गॅस मर्यादा 2016 पासून आजपर्यंत क्वेरी आणि व्हिज्युअलाइझ केली जाऊ शकते:

![Chart showing average Ethereum gas limit over time](./avg_gas_limit.png)

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    AVG(gas_limit) AS avg_block_gas_limit
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

त्यानंतर इथेरियम चेनवर केलेल्या संगणनासाठी (उदा. व्यवहार पाठवणे, स्मार्ट कॉन्ट्रॅक्ट कॉल करणे, नॉन-फंजिबल टोकन (NFT) मिंटिंग करणे) पैसे देण्यासाठी दररोज वापरला जाणारा प्रत्यक्ष गॅस आहे. ही उपलब्ध इथेरियम ब्लॉक स्पेसची **मागणी** आहे:

![Chart showing daily Ethereum gas used](./daily_gas_used.png)

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    AVG(gas_used) AS avg_block_gas_used
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

**मागणी आणि पुरवठा** कसे जुळतात हे पाहण्यासाठी आपण हे दोन चार्ट एकत्र देखील ठेवू शकतो:

![gas_demand_supply](./gas_demand_supply.png)

म्हणून आपण उपलब्ध पुरवठा लक्षात घेता, इथेरियम ब्लॉक स्पेसच्या मागणीचे कार्य म्हणून गॅसच्या किमती समजू शकतो.

शेवटी, आपल्याला इथेरियम चेनसाठी सरासरी दैनंदिन गॅस किमतींची क्वेरी करायची असू शकते, तथापि, असे केल्याने क्वेरीसाठी खूप वेळ लागेल, म्हणून आपण आपली क्वेरी इथेरियम फाउंडेशनद्वारे प्रति व्यवहार भरलेल्या गॅसच्या सरासरी रकमेवर फिल्टर करू.

![Chart showing Ethereum Foundation daily gas usage](./ef_daily_gas.png)

आपण गेल्या काही वर्षांत इथेरियम फाउंडेशनच्या पत्त्यावर केलेल्या सर्व व्यवहारांसाठी भरलेल्या गॅसच्या किमती पाहू शकतो. येथे क्वेरी आहे:

```sql
SELECT
    block_time,
    gas_price / 1e9 AS gas_price_gwei,
    value / 1e18 AS eth_sent
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
```
