बहुतेक मोठ्या इथेरियम एक्सप्लॉइट्समध्ये एकच अंतिम पायरी होती: वापरकर्त्याने असा व्यवहार मंजूर करणे जो त्यांना अर्थपूर्णरीत्या समजू शकत नव्हता. हार्डवेअर वॉलेट्स कच्चा हेक्स कॉल डेटा दाखवतात आणि त्याहून वाईट म्हणजे तुम्हाला ब्लाइंड स्वाक्षरी करणे चालू ठेवण्यास भाग पाडतात. सॉफ्टवेअर वॉलेट्स डीकोड केलेले फील्ड्स दाखवतात, परंतु केवळ तेव्हाच जेव्हा ते कॉन्ट्रॅक्ट ओळखतात. जेव्हा ते ओळखत नाहीत, मग ते प्रोटोकॉल नवीन असल्यामुळे असो, ॲप तडजोड केलेले (compromised) असल्यामुळे असो किंवा डिव्हाइस ऑफलाइन असल्यामुळे असो, वापरकर्ते ब्लाइंड स्वाक्षरी करतात.

[ERC-7730](https://eips.ethereum.org/EIPS/eip-7730) तुमच्या कॉन्ट्रॅक्टच्या फंक्शन कॉल्सचा *अर्थ* काय आहे याचे वर्णन करण्यासाठी एक मानक JSON फॉरमॅट परिभाषित करते.

ERC-7730 ला सपोर्ट करणारे वॉलेट तुमचा डिस्क्रिप्टर वाचते आणि दाखवते:

> **अदलाबदल**  
> पाठवा: 1,000 USDC  
> किमान प्राप्त करा: 0.42 WETH  
> प्रोटोकॉल: Uniswap V2

किंवा मानवांना आणि एजंट्सना वाचता येईल असे एकच तयार केलेले वाक्य:

> किमान 0.42 WETH साठी 1,000 USDC ची अदलाबदल करा

फंक्शन सिलेक्टर आणि कच्च्या पूर्णांक मूल्यांच्या सूचीऐवजी.

याला [क्लिअर स्वाक्षरी करणे](https://clearsigning.org/) म्हणतात — "तुम्ही जे पाहता त्यावरच तुम्ही स्वाक्षरी करता." हे ट्युटोरियल तुम्हाला तुमच्या स्वतःच्या कॉन्ट्रॅक्टसाठी डिस्क्रिप्टर लिहिणे, अधिकृत CLI टूलसह ते प्रमाणित करणे आणि ओपन रजिस्ट्रीमध्ये सबमिट करणे याबद्दल मार्गदर्शन करते.

## पूर्वअटी {#prerequisites}

- Solidity आणि स्मार्ट कॉन्ट्रॅक्ट ABIs ची माहिती
- सत्यापित ABI सह प्रस्थापित केलेले स्मार्ट कॉन्ट्रॅक्ट (डिस्क्रिप्टर रजिस्ट्रीमध्ये स्वीकारण्यापूर्वी [Sourcify](https://sourcify.dev) सत्यापन आवश्यक आहे)
- प्रमाणीकरण CLI साठी Python 3.12 (पिन केलेले `erc7730` पॅकेज Python 3.13 किंवा नंतरच्या आवृत्तीवर इन्स्टॉल होत नाही). जर तुमच्या सिस्टीममधील Python ची आवृत्ती वेगळी असेल, तर [uv](https://docs.astral.sh/uv/) तुमच्यासाठी Python 3.12 डाउनलोड करून रन करू शकते
- JSON चे मूलभूत ज्ञान

## ERC-7730 डिस्क्रिप्टर म्हणजे काय? {#what-is-an-erc-7730-descriptor}

डिस्क्रिप्टर ही तीन विभागांसह असलेली एकच JSON फाईल असते:

| विभाग (Section) | उद्देश (Purpose) |
| :---- | :---- |
| `context` | चेन आयडी (chain ID) आणि पत्त्याद्वारे डिस्क्रिप्टरला विशिष्ट कॉन्ट्रॅक्ट प्रस्थापनांशी (deployments) जोडते |
| `metadata` | प्रकल्पाला नाव देते आणि पुन्हा वापरता येण्याजोगे स्थिरांक (constants) परिभाषित करते |
| `display` | प्रत्येक फंक्शन स्वाक्षरीला मानवी-वाचनीय लेबल्स आणि फील्ड फॉरमॅट्सशी मॅप करते |

डिस्क्रिप्टर कॉन्ट्रॅक्टपासून वेगळा असल्यामुळे, तुम्ही पुन्हा प्रस्थापना (redeployment) न करता कोणत्याही विद्यमान प्रोटोकॉलमध्ये क्लिअर स्वाक्षरी सपोर्ट जोडू शकता. वॉलेट्स रजिस्ट्रीमधून डिस्क्रिप्टर्स मिळवतात आणि स्वाक्षरी करण्याच्या वेळी त्यांचा वापर करतात.

## पायरी 1: फाईल सांगाडा (skeleton) तयार करा {#step-1-create-the-file-skeleton}

`calldata-<ContractName>.json` नावाचे फाईल तयार करा, उदाहरणार्थ `calldata-SwapRouter.json`. `calldata-` उपसर्ग (prefix) रजिस्ट्रीला सांगतो की हा डिस्क्रिप्टर कॉन्ट्रॅक्ट फंक्शन कॉल्स कव्हर करतो, जे टाईप-डेटा मेसेजेससाठी असलेल्या `eip712-` च्या विरुद्ध आहे. जर तुम्हाला कॉन्ट्रॅक्टच्या अनेक आवृत्त्यांचे वर्णन करायचे असेल, तर नावात कॉन्ट्रॅक्टची आवृत्ती समाविष्ट करा, जसे की रजिस्ट्रीच्या `calldata-UniswapV3Router02.json` मध्ये आहे.

```json
{
  "$schema": "https://eips.ethereum.org/assets/eip-7730/erc7730-v2.schema.json",
  "context": {},
  "metadata": {},
  "display": {
    "formats": {}
  }
}
```

## पायरी 2: संदर्भ (context) विभाग लिहा {#step-2-write-the-context-section}

`context` विभाग डिस्क्रिप्टरला एक किंवा अधिक कॉन्ट्रॅक्ट प्रस्थापनांशी (deployments) जोडतो. येणाऱ्या व्यवहाराला योग्य डिस्क्रिप्टरशी जुळवण्यासाठी वॉलेट्स याचा वापर करतात.

```json
"context": {
  "$id": "example-swap-router",
  "contract": {
    "deployments": [
      { "chainId": 1, "address": "0xYourContractAddressOnMainnet" },
      { "chainId": 137, "address": "0xYourContractAddressOnPolygon" }
    ]
  }
}
```

### संदर्भ फील्ड्स (Context fields) {#context-fields}

- `context.$id` — या डिस्क्रिप्टर दस्तऐवजासाठी किंवा प्रस्थापना कॉन्फिगरेशनसाठी एक युनिक आयडेंटिफायर.
- `contract.deployments` — हा डिस्क्रिप्टर ज्या प्रस्थापनांना लागू होतो त्यांचा संच.
- `deployments[].chainId` — प्रस्थापनेसाठी EVM चेन आयडी (chain ID). तुमचे कॉन्ट्रॅक्ट प्रस्थापित केलेल्या प्रत्येक चेनचा समावेश करा.
- `deployments[].address` — वॉलेट्सनी या डिस्क्रिप्टरशी जोडला पाहिजे असा कॉन्ट्रॅक्ट पत्ता. हा तो पत्ता आहे ज्यावर वापरकर्ते प्रत्यक्षात व्यवहार पाठवतात. जर तुमचे कॉन्ट्रॅक्ट अपग्रेड करण्यायोग्य असेल, तर तो प्रॉक्सी पत्ता आहे, अंमलबजावणीचा (implementation) पत्ता नाही, तर `display.formats` मधील फंक्शन स्वाक्षऱ्या अंमलबजावणीच्या ABI मधून येतात.

## पायरी 3: मेटाडेटा विभाग लिहा {#step-3-write-the-metadata-section}

मेटाडेटा विभाग या फाईलद्वारे वर्णन केलेल्या प्रकल्पाबद्दल आणि कॉन्ट्रॅक्टबद्दल मानवी-वाचनीय माहिती प्रदान करतो. वॉलेट्स स्वाक्षरी करताना प्रोटोकॉलची नावे, लिंक्स आणि इतर संदर्भात्मक तपशील प्रदर्शित करण्यासाठी या माहितीचा वापर करू शकतात.

```json
"metadata": {
  "owner": "Example Swap Protocol",
  "info": { "url": "https://example.xyz" },
  "contractName": "SwapRouter"
}
```

### मेटाडेटा फील्ड्स {#metadata-fields}

- `owner` — या डिस्क्रिप्टरसाठी जबाबदार असलेला प्रकल्प, प्रोटोकॉल, संस्था किंवा देखभालकर्ता (maintainer).
- `info.url` — अतिरिक्त संदर्भासाठी वॉलेट्स वापरकर्त्यांना दाखवू शकतील अशी अधिकृत प्रकल्प किंवा दस्तऐवजीकरण URL.
- `contractName` — या फाईलद्वारे वर्णन केलेले कॉन्ट्रॅक्ट किंवा अंमलबजावणीचे नाव, जे सामान्यतः सत्यापित सोर्स कोड किंवा ABI शी जुळते.

जर तुमची ERC-7730 फाईल ERC-20 कॉन्ट्रॅक्टचे वर्णन करत असेल, तर तुम्ही टोकन ऑब्जेक्ट देखील जोडला पाहिजे. 

## पायरी 4: डिस्प्ले फॉरमॅट्स विभाग लिहा {#step-4-write-the-displayformats-section}

`display.formats` ऑब्जेक्ट फंक्शन स्वाक्षऱ्या मानवी-वाचनीय स्वाक्षरी सूचनांशी मॅप करतो. अशा प्रकारे वापरकर्त्यांनी व्यवहार मंजूर करण्यापूर्वी वॉलेट्स तुमचे फंक्शन त्यांना दाखवतात!

प्रत्येक की (key) एक मानवी-वाचनीय ABI फ्रॅगमेंट आहे — फंक्शन स्वाक्षरी ज्यामध्ये पॅरामीटरची नावे आणि पॅरामीटरचे प्रकार दोन्ही तुमच्या ABI मध्ये जसे दिसतात अगदी तसेच समाविष्ट असतात.


### उदाहरण: टोकन अदलाबदलीचे वर्णन करणे {#eg-describing-token-swap}

हे उदाहरण Uniswap V2 `Router02` कॉन्ट्रॅक्टमधील `swapExactTokensForTokens` चे वर्णन करते. इनपुट टोकन हा `path` चा पहिला घटक आहे आणि आउटपुट टोकन हा शेवटचा घटक आहे (मल्टी-हॉप अदलाबदलीसाठी `path` मध्ये दोनपेक्षा जास्त घटक असू शकतात).

```json
"display": {
  "formats": {
    "swapExactTokensForTokens(uint256 amountIn,uint256 amountOutMin,address[] path,address to,uint256 deadline)": {
      "intent": "Swap",
      "interpolatedIntent": "Swap {amountIn} for at least {amountOutMin}",
      "fields": [
        {
          "path": "#.amountIn",
          "label": "Send",
          "format": "tokenAmount",
          "params": {
            "tokenPath": "#.path.[0]"
          }
        },
        {
          "path": "#.amountOutMin",
          "label": "Receive minimum",
          "format": "tokenAmount",
          "params": {
            "tokenPath": "#.path.[-1]"
          }
        },
        {
          "path": "#.to",
          "label": "Recipient",
          "format": "addressName",
          "params": {
            "types": ["eoa", "contract"],
            "sources": ["local", "ens"]
          }
        },
        {
          "path": "#.deadline",
          "label": "Expires",
          "format": "date",
          "params": {
            "encoding": "timestamp"
          }
        }
      ]
    }
  }
}
```

### डिस्प्ले फील्ड्स (Display fields) {#display-fields}

- **`intent`** — **(आवश्यक)** क्रियेचे एक लहान, वापरकर्ता-अनुकूल वर्णन, जसे की "अदलाबदल (Swap)".
- **`interpolatedIntent`** — **(शिफारस केलेले)** एक अधिक समृद्ध वाक्य टेम्पलेट जे फॉरमॅट केलेली फील्ड मूल्ये एम्बेड करते, जसे की `"Swap {amountIn} for at least {amountOutMin}"`. वॉलेट्स कोणत्याही डिस्प्ले मर्यादांनुसार दाखवण्यासाठी निवडू शकतील असा आणखी वापरकर्ता-अनुकूल डिस्क्रिप्टर प्रदान करण्यासाठी `intent` सोबत याचा समावेश करा.
- **`fields`** — **(आवश्यक)** वॉलेट्सनी वापरकर्त्यांना दाखवल्या पाहिजेत अशा व्यवहार फील्ड्सची क्रमित सूची.
  - **`path`** — **(आवश्यक)** व्यवहार डेटाचा संदर्भ. `#.fieldName` ABI मधील नावानुसार डीकोड केलेल्या कॉल डेटा पॅरामीटरकडे निर्देश करते. `@.value` व्यवहारासोबत पाठवलेल्या ETH मूल्याचा संदर्भ देते. ॲरे (Array) घटक कंसाच्या आधी `.` सह लिहिले जातात: `#.path.[0]` हा पहिला घटक आहे आणि `#.path.[-1]` हा शेवटचा. `#.path[0]` (डॉटशिवाय) लिंटरद्वारे (linter) नाकारले जाते.
  - **`label`** — **(आवश्यक)** मूल्याच्या बाजूला दाखवलेले मानवी-वाचनीय लेबल.
  - **`format`** — **(शिफारस केलेले)** मूल्य कसे रेंडर केले जावे हे नियंत्रित करते. सामान्य फॉरमॅट्समध्ये हे समाविष्ट आहे:
    - `tokenAmount`
    - `addressName`
    - `date`

    जेव्हा कोणत्याही अतिरिक्त फॉरमॅटिंगची आवश्यकता नसते तेव्हा `raw` वापरा. काही फॉरमॅट्स अतिरिक्त **`params`** कॉन्फिगरेशन स्वीकारतात. उदाहरणार्थ:

    - `tokenAmount` कोणता टोकन पत्ता डेसिमल्स आणि टिकर मेटाडेटा प्रदान करतो हे ओळखण्यासाठी `tokenPath` वापरू शकते.
    - `date` टाइमस्टॅम्प कसा एन्कोड केला आहे याचे वर्णन करण्यासाठी `encoding` वापरू शकते.

    जर निवडलेल्या फॉरमॅटला अतिरिक्त माहितीची आवश्यकता नसेल, तर `params` वगळा.

## संपूर्ण डिस्क्रिप्टर {#the-complete-descriptor}

प्लेसहोल्डर पत्त्यांच्या जागी तुमच्या प्रस्थापित केलेल्या कॉन्ट्रॅक्टचे पत्ते टाका. लिंटर त्या पत्त्यांवरील सत्यापित ABI विरुद्ध डिस्क्रिप्टर तपासतो, त्यामुळे तुम्ही तसे करेपर्यंत तो त्रुटी नोंदवतो.

```json
{
  "$schema": "https://eips.ethereum.org/assets/eip-7730/erc7730-v2.schema.json",
  "context": {
    "$id": "example-swap-router",
    "contract": {
      "deployments": [
        {
          "chainId": 1,
          "address": "0xYourContractAddressOnMainnet"
        },
        {
          "chainId": 137,
          "address": "0xYourContractAddressOnPolygon"
        }
      ]
    }
  },
  "metadata": {
    "owner": "Example Swap Protocol",
    "info": {
      "url": "https://example.xyz"
    },
    "contractName": "SwapRouter"
  },
  "display": {
    "formats": {
      "swapExactTokensForTokens(uint256 amountIn,uint256 amountOutMin,address[] path,address to,uint256 deadline)": {
        "intent": "Swap",

        "fields": [
```

## पायरी 5: रजिस्ट्रीमध्ये सबमिट करा {#step-5-submit-to-the-registry}

[ERC-7730 रजिस्ट्री](https://github.com/ethereum/clear-signing-erc7730-registry) ही एक तटस्थ व्यवस्थापक (neutral steward) म्हणून [इथेरियम फाउंडेशन](/foundation/) द्वारे होस्ट केलेली ओपन रिपॉझिटरी आहे. कोणालाही ती क्लोन आणि सेल्फ-होस्ट करण्याचे स्वातंत्र्य आहे — वॉलेट्स स्वतंत्रपणे ठरवतात की ते कोणत्या रजिस्ट्री इन्स्टन्सेसवर विश्वास ठेवतात.

1. GitHub वर रिपॉझिटरी फोर्क (Fork) करा
2. `registry/<your-project-name>/` येथे एक फोल्डर तयार करा
3. तुमची फाईल त्यामध्ये ठेवा: `registry/myproject/calldata-SwapRouter.json`
4. `$schema` फील्डला रेपोमध्ये वापरलेल्या रिलेटिव्ह पाथवर अपडेट करा: `"../../specs/erc7730-v2.schema.json"`. CI येथे URL नाकारते.
5. एक टेस्ट फाईल जोडा (खाली पहा)
6. तुमच्या फाईल्स लोकली प्रमाणित करा (खाली पहा)
7. एक पुल रिक्वेस्ट (pull request) उघडा. प्रत्येक पुल रिक्वेस्ट `registry/` अंतर्गत फक्त एकच फोल्डर बदलू शकते

### एक टेस्ट फाईल जोडा {#add-a-test-file}

तुम्ही जोडलेल्या किंवा बदललेल्या प्रत्येक डिस्क्रिप्टरला एका टेस्ट फाईलची आवश्यकता असते, जेणेकरून क्लिअर स्वाक्षरी अंमलबजावणी (clear signing implementations) त्याविरुद्ध तपासली जाऊ शकेल. `display.formats` मधील प्रत्येक फंक्शनसाठी किमान एका टेस्ट केससह `registry/<your-project-name>/testsv2/calldata-<ContractName>.tests.json` तयार करा. CI प्रत्येक फॉरमॅटचा फंक्शन सिलेक्टर मिळवते आणि जर कोणत्याही टेस्ट व्यवहाराने त्याला कॉल केले नाही तर ते अयशस्वी होते.

```json
{
  "$schema": "../../../specs/erc7730-tests-v2.schema.json",
  "descriptor": "../calldata-SwapRouter.json",
  "dataProvider": {
    "tokens": {
      "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48": { "symbol": "USDC", "decimals": 6, "name": "USD Coin" },
      "0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2": { "symbol": "WETH", "decimals": 18, "name": "Wrapped Ether" }
    }
  },
  "tests": [
    {
      "description": "Swap 1,000 USDC for at least 0.42 WETH",
      "rawTx": "0x02f9012f0180843b9aca00...",
      "expected": {
        "intent": "Swap",
        "interpolatedIntent": "Swap 1000 USDC for at least 0.42 WETH",
        "owner": "Example Swap Protocol",
        "fields": [
          { "label": "Send", "value": "1000 USDC" },
          { "label": "Receive minimum", "value": "0.42 WETH" },
          { "label": "Recipient", "value": "0x1234567890123456789012345678901234567890" },
          { "label": "Expires", "value": "2026-01-01 00:00:00Z" }
        ]
      }
    }
  ]
}
```

- `rawTx` हा संपूर्ण सीरियलाइज्ड **स्वाक्षरी नसलेला (unsigned)** व्यवहार आहे (येथे लहान केलेला), केवळ कॉल डेटा नाही. तुमच्या कॉन्ट्रॅक्टवरील वास्तविक व्यवहार हे सर्वोत्तम टेस्ट केसेस आहेत.
- `dataProvider` टोकन मेटाडेटा (आणि पर्यायाने पत्ता आणि ENS नावे) पुरवते जेणेकरून टेस्ट्सना नेटवर्क ॲक्सेसची आवश्यकता नसते.
- `expected` हे वॉलेटने काय दाखवले पाहिजे ते आहे. CI क्लिअर स्वाक्षरी अंमलबजावणीसह प्रत्येक टेस्ट केस रेंडर करते आणि पुल रिक्वेस्टवर कोणतेही फरक नोंदवते.

EIP-712 डिस्क्रिप्टर्ससाठी टेस्ट फाईल्ससह संपूर्ण फॉरमॅटसाठी रजिस्ट्री README मधील [संदर्भ टेस्ट केसेस (Reference test cases)](https://github.com/ethereum/clear-signing-erc7730-registry#reference-test-cases) पहा.

### लोकली प्रमाणित करा {#validate-locally}

रजिस्ट्री `.github/requirements.txt` मध्ये पिन केलेल्या [`erc7730`](https://github.com/sourcifyeth/python-erc7730) कमांड-लाईन टूलसह डिस्क्रिप्टर्स तपासते. Python 3.12 वातावरणात, तुमच्या फोर्कच्या (fork) रूटवरून ते रन करा:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r .github/requirements.txt
erc7730 lint registry/myproject/calldata-SwapRouter.json
```

जर तुम्ही [uv](https://docs.astral.sh/uv/) वापरत असाल, तर तुम्ही व्हर्च्युअल वातावरण वगळू शकता आणि आवश्यक असल्यास uv Python 3.12 डाउनलोड करते:

```sh
uvx --python 3.12 --from "$(cat .github/requirements.txt)" erc7730 lint registry/myproject/calldata-SwapRouter.json
```

लिंटर स्कीमा (schema) आणि तुमच्या कॉन्ट्रॅक्टच्या सत्यापित ABI विरुद्ध डिस्क्रिप्टर तपासतो. प्रत्येक त्रुटी दुरुस्त करा. `Missing display format` सारख्या इशाऱ्यांचा अर्थ असा आहे की कॉन्ट्रॅक्टमध्ये अशी फंक्शन्स आहेत ज्यांचे वर्णन तुमच्या डिस्क्रिप्टरने अद्याप केलेले नाही. CI ज्याप्रमाणे करते तसे `$schema` पाथ्स आणि टेस्ट फाईल तपासण्यासाठी, रजिस्ट्री README मधील [कसे प्रमाणित करावे (How to validate)](https://github.com/ethereum/clear-signing-erc7730-registry#how-to-validate) पहा.

जेव्हा तुम्ही PR उघडता, तेव्हा CI आपोआप स्कीमा प्रमाणीकरण रन करते, फंक्शन स्वाक्षऱ्या वैध सिलेक्टर्स तयार करतात हे तपासते, कॉन्ट्रॅक्ट पत्ता Sourcify वर सत्यापित असल्याची पुष्टी करते आणि ABI विसंगती फ्लॅग करते. तपासणीचे परिणाम PR वर इनलाइन दिसतात. रजिस्ट्री देखभालकर्ते (maintainers) चुकीच्या किंवा संभाव्य दुर्भावनापूर्ण डिस्क्रिप्टर्ससाठी सबमिशन्स तपासतात. रजिस्ट्रीमध्ये समाविष्ट करणे म्हणजे ऑडिट किंवा समर्थन (endorsement) सूचित करत नाही.

## विलीनीकरणानंतर (merging) काय होते? {#what-happens-after-merging}

रजिस्ट्रीमधील सर्व डिस्क्रिप्टर्स ऑडिटर्ससाठी खुले असतात. तुमची PR विलीन झाल्यानंतर, कोणताही ऑडिटर तुमच्या डिस्क्रिप्टरचे पुनरावलोकन करू शकतो आणि त्याच्या अचूकतेची पुष्टी करणारे क्रिप्टोग्राफिक साक्षांकन ([ERC-8176](https://eips.ethereum.org/EIPS/eip-8176) अंतर्गत) प्रकाशित करू शकतो. 

हे साक्षांकन सिग्नल्स वॉलेट्सना त्यांची स्वतःची विश्वास धोरणे (trust policies) लागू करू देतात — एकाधिक स्वतंत्र साक्षांकन असलेल्या डिस्क्रिप्टरला त्याशिवाय असलेल्या डिस्क्रिप्टरपेक्षा जास्त महत्त्व असते. तुम्ही [clearsigning.org](https://clearsigning.org) द्वारे ऑडिटर समुदायापर्यंत पोहोचू शकता.

वॉलेट्स ते कोणत्या रजिस्ट्रीला सपोर्ट करतील हे निवडतात. एकदा तुमचा डिस्क्रिप्टर रजिस्ट्रीमध्ये आला की, ERC-7730 ला सपोर्ट करणारी वॉलेट्स तो त्यांच्या रजिस्ट्रीमध्ये असल्यास मिळवणे सुरू करतील आणि जेव्हा वापरकर्ते तुमच्या कॉन्ट्रॅक्टशी संवाद साधतील तेव्हा मानवी-वाचनीय डेटा प्रदर्शित करतील.
