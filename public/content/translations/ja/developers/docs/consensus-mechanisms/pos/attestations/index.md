バリデータは、各エポック中にアテステーションを作成、署名、およびブロードキャストすることが期待されています。このページでは、これらのアテステーションがどのようなものか、またコンセンサス・クライアント間でどのように処理され、通信されるかについて概説します。

## アテステーションとは？ {#what-is-an-attestation}

バリデータは、[エポック](/glossary/#epoch)（6.4分）ごとにアテステーションをネットワークにブロードキャストします。アテステーションは、エポック内の特定のスロットに対するものです。アテステーションの目的は、バリデータが認識しているチェーンのビュー、特にチェーンの先頭（head）、直近のジャスティファイド・チェックポイント、および現在のエポックの開始時のチェックポイント（`source`および`target`チェックポイントとして知られています）に賛成の投票を行うことです。この情報は参加しているすべてのバリデータについて結合され、ネットワークがブロックチェーンの状態に関するコンセンサスに達することを可能にします。

[ペクトラ・アップグレード](/roadmap/pectra/)（[EIP-7549](https://eips.ethereum.org/EIPS/eip-7549)）以降、単一のバリデータからのアテステーションと集約されたアテステーションは異なるフォーマットを持っています。単一のバリデータのアテステーションには以下が含まれます。

- `committee_index`: 指定されたスロットでバリデータが属するコミッティ
- `attester_index`: バリデータのインデックス
- `data`: 以下で定義される、アテステーションに関する詳細
- `signature`: `data`に対するバリデータのBLS署名

アテステーションを行うバリデータの最初のタスクは、`data`を構築することです。`data`には以下の情報が含まれます。

- `slot`: アテステーションが参照するスロット番号
- `index`: ペクトラ以降、`0`に設定されます。異なるコミッティからの投票が同一の`data`を持ち、一緒に集約できるように、コミッティは`data`の外部（`committee_index`、または集約の場合は`committee_bits`）で識別されます。ペクトラ以前は、このフィールドがコミッティを識別していました。
- `beacon_block_root`: バリデータがチェーンの先頭と見なすブロックのルートハッシュ（フォークチョイス・アルゴリズムを適用した結果）
- `source`: バリデータが直近のジャスティファイド・チェックポイントと見なすものを示す、ファイナリティ投票の一部
- `target`: バリデータが現在のエポックの開始時のチェックポイント（最初のスロットのブロック、またはそのスロットが空の場合はその前の最新ブロック）と見なすものを示す、ファイナリティ投票の一部

`data`が構築されると、バリデータはそれに署名し、自身のコミッティの[サブネット](#aggregated-attestation)にアテステーションをブロードキャストします。

### 集約されたアテステーション {#aggregated-attestation}

すべてのバリデータについてこのデータをネットワーク上でやり取りすることには、かなりのオーバーヘッドが伴います。そのため、個々のバリデータからのアテステーションは、より広くブロードキャストされる前にサブネット内で集約されます。これには署名の集約も含まれるため、ブロードキャストされるアテステーションには、コンセンサス`data`と、その`data`に同意するすべてのバリデータの署名を組み合わせて形成された単一の署名が含まれます。集約されたアテステーションには以下が含まれます。

- `aggregation_bits`: 含まれる各コミッティのメンバーごとに1ビットを持つビットリスト。位置はコミッティ内のバリデータの位置にマッピングされ、値（0/1）はそのバリデータの署名が含まれているかどうかを示します。
- `data`: 含まれるすべてのバリデータが署名したアテステーション・データ
- `signature`: 含まれるバリデータの署名を集約したBLS署名
- `committee_bits`: `aggregation_bits`がどのコミッティのメンバーをカバーしているか

誰でも、ビットが設定されているバリデータの公開鍵を組み合わせたものと照らし合わせて、集約された署名を確認することができます。

各スロットにおいて、各コミッティの約16人のメンバーが`aggregators`（`TARGET_AGGREGATORS_PER_COMMITTEE`）として選出されます。バリデータは、スロット番号に対する自身の署名から、自分が選出されたかどうかを知ります。アグリゲーターは、自身のコミッティのサブネットで受信した、自身と同じ`data`を持つすべてのアテステーションを収集して組み合わせ、それぞれの送信者を`aggregation_bits`に記録します。その後、アグリゲーターは集約されたものをより広いネットワークにブロードキャストします。

バリデータがブロック・プロポーザーとして選出されると、最近のスロットからの集約されたアテステーションを新しいブロックに含めます。ペクトラ以降、プロポーザーは同じ`data`を共有する異なるコミッティからの集約を1つのアテステーションにマージできるようになり、1つのブロックには最大8つのアテステーションを保持できます。

## 報酬 {#rewards}

バリデータはアテステーションを提出することで報酬を受け取ります。アテステーション報酬は、参加フラグ（ソース、ターゲット、およびヘッド）、基本報酬、および参加率に依存します。

各参加フラグは、提出されたアテステーションとそのインクルージョン遅延に応じて、trueまたはfalseのいずれかになります。

最良のシナリオは、3つのフラグすべてがtrueの場合に発生し、その場合バリデータは（正しいフラグごとに）以下を獲得します。

`reward += base reward * flag weight * flag attesting rate / 64`

フラグのアテステーション率は、指定されたフラグに対してアテステーションを行ったすべてのバリデータのエフェクティブ・バランスの合計を、アクティブなエフェクティブ・バランスの総計と比較して測定されます。

### 基本報酬 {#base-reward}

基本報酬は、アテステーションを行うバリデータの数と、それらのステークされたイーサのエフェクティブ・バランスに基づいて計算されます。

`base reward = validator effective balance x 2^6 / SQRT(Effective balance of all active validators)`

#### インクルージョン遅延 {#inclusion-delay}

バリデータがチェーンの先頭（`block n`）に投票した時点では、`block n+1`はまだ提案されていませんでした。したがって、アテステーションは当然**1ブロック後**にインクルードされるため、`block n`がチェーンの先頭であると投票したすべてのアテステーションは`block n+1`にインクルードされ、**インクルージョン遅延**は1になります。インクルージョン遅延は、アテステーションがどの参加フラグを獲得するかを決定します。

- `head`: インクルージョン遅延が正確に1スロットの場合のみ
- `source`: インクルージョン遅延が最大5スロット（1エポック内の32スロットの整数平方根）の場合
- `target`: アテステーションがインクルードされた場合はいつでも（Denebアップグレード以降、[EIP-7045](https://eips.ethereum.org/EIPS/eip-7045)）

したがって、2スロット遅れてインクルードされたアテステーションはヘッド報酬を失いますが、ソース報酬とターゲット報酬は引き続き獲得します。

### アテステーションのシナリオ {#attestation-scenarios}

#### 投票するバリデータの欠落 {#missing-voting-validator}

アテステーションは、それが作成された次のスロットから次のエポックの終わりまでの任意のブロックにインクルードされる可能性があります。エポック0からのアテステーションがエポック0の間にブロックにインクルードされなかった場合でも、インクルージョン遅延は長くなりますが、エポック1でインクルードされる可能性があります。

#### アグリゲーターの欠落 {#missing-aggregator}

各コミッティはすべてのスロットで約16人のアグリゲーターを目指しているため、1人のアグリゲーターが欠落しても、コミッティのアテステーションの集約が停止することはめったにありません。これとは別に、すべてのビーコン・ノードは、ノードIDから選択された**2つのサブネットに一度に256エポック**の間サブスクライブし続けるため、すべてのサブネットが適切に接続された状態に保たれます。

#### ブロック・プロポーザーの欠落 {#missing-block-proposer}

場合によっては、運の良いアグリゲーターがブロック・プロポーザーになることもある点に注意してください。ブロック・プロポーザーが欠落したためにアテステーションがインクルードされなかった場合、次のブロック・プロポーザーが集約されたアテステーションを拾い上げ、次のブロックにインクルードします。ただし、**インクルージョン遅延**は1増加します。
