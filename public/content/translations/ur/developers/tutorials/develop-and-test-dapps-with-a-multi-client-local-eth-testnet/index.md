## تعارف {#introduction}

یہ گائیڈ آپ کو ایک قابلِ تشکیل مقامی ایتھیریم آزمائشی نیٹ ورک شروع کرنے، اس پر ایک سمارٹ کنٹریکٹ تعینات کرنے، اور اپنی غیر مرکزی ایپلی کیشن (dapp) کے خلاف ٹیسٹ چلانے کے لیے آزمائشی نیٹ ورک کا استعمال کرنے کے عمل سے آگاہ کرتی ہے۔ یہ گائیڈ ان dapp ڈیولپرز کے لیے بنائی گئی ہے جو لائیو آزمائشی نیٹ ورک یا مین نیٹ پر تعینات کرنے سے پہلے مختلف نیٹ ورک کنفیگریشنز کے خلاف مقامی طور پر اپنی dapps تیار اور ٹیسٹ کرنا چاہتے ہیں۔

اس گائیڈ میں، آپ یہ کریں گے:

- [Kurtosis](https://www.kurtosis.com/) کا استعمال کرتے ہوئے [`ethereum-package`](https://github.com/ethpandaops/ethereum-package) کے ساتھ ایک مقامی ایتھیریم آزمائشی نیٹ ورک شروع کریں گے،
- ایک dapp کو مرتب کرنے، تعینات کرنے اور ٹیسٹ کرنے کے لیے اپنے Hardhat dapp ڈیولپمنٹ ماحول کو مقامی آزمائشی نیٹ ورک سے جوڑیں گے، اور
- مختلف نیٹ ورک کنفیگریشنز کے خلاف ڈیولپمنٹ اور ٹیسٹنگ ورک فلو کو فعال کرنے کے لیے مقامی آزمائشی نیٹ ورک کو کنفیگر کریں گے، جس میں نوڈز کی تعداد اور مخصوص EL/CL کلائنٹ کی جوڑیوں جیسے پیرامیٹرز شامل ہیں۔

### Kurtosis کیا ہے؟ {#what-is-kurtosis}

[Kurtosis](https://www.kurtosis.com/) ایک قابلِ ترکیب بلڈ سسٹم ہے جسے ملٹی کنٹینر ٹیسٹ ماحول کو کنفیگر کرنے کے لیے ڈیزائن کیا گیا ہے۔ یہ خاص طور پر ڈیولپرز کو ایسے قابلِ تولید ماحول بنانے کے قابل بناتا ہے جن کے لیے متحرک سیٹ اپ لاجک کی ضرورت ہوتی ہے، جیسے کہ بلاک چین آزمائشی نیٹ ورکس۔

اس گائیڈ میں، Kurtosis `ethereum-package`، جسے [ethPandaOps](https://ethpandaops.io/) کے ذریعے برقرار رکھا گیا ہے، ایک مقامی ایتھیریم آزمائشی نیٹ ورک شروع کرتا ہے۔ یہ تمام بڑے عمل درآمد کی تہہ (EL) کلائنٹس، جیسے [`geth`](https://geth.ethereum.org/)، اور اتفاق رائے کی تہہ (CL) کلائنٹس، جیسے [`teku`](https://consensys.io/teku)، [`lighthouse`](https://lighthouse.sigmaprime.io/)، اور [`lodestar`](https://lodestar.chainsafe.io/) کو سپورٹ کرتا ہے۔ یہ پیکیج Hardhat Network اور Anvil جیسے فریم ورکس میں نیٹ ورکس کے لیے ایک قابلِ تشکیل اور قابلِ ترکیب متبادل کے طور پر کام کرتا ہے۔ Kurtosis ڈیولپرز کو ان کے استعمال کردہ آزمائشی نیٹ ورکس پر زیادہ کنٹرول اور لچک فراہم کرتا ہے، جو ایک بڑی وجہ ہے کہ ایتھیریم کلائنٹ ٹیمیں اسے نیٹ ورک اپ گریڈ کی ٹیسٹنگ کے لیے استعمال کرتی ہیں۔

## Kurtosis کو ترتیب دینا {#setting-up-kurtosis}

آگے بڑھنے سے پہلے، یقینی بنائیں کہ آپ کے پاس یہ موجود ہیں:

- اپنی مقامی مشین پر [Docker انجن انسٹال اور شروع کر لیا ہے](https://docs.kurtosis.com/install/#i-install--start-docker)
- [Kurtosis CLI انسٹال کر لی ہے](https://docs.kurtosis.com/install#ii-install-the-cli) (یا اگر آپ کے پاس پہلے سے ہی CLI انسٹال ہے تو اسے تازہ ترین ریلیز میں اپ گریڈ کر لیا ہے)
- [Node.js](https://nodejs.org/en) انسٹال کر لیا ہے (آپ کے dapp ماحول کے لیے)

## ایک مقامی ایتھیریم آزمائشی نیٹ ورک شروع کرنا {#instantiate-testnet}

ایک مقامی ایتھیریم آزمائشی نیٹ ورک شروع کرنے کے لیے، چلائیں:

```sh
kurtosis run --enclave local-eth-testnet github.com/ethpandaops/ethereum-package
```

نوٹ: یہ کمانڈ `--enclave` فلیگ کا استعمال کرتے ہوئے آپ کے نیٹ ورک کا نام "local-eth-testnet" رکھتی ہے۔

Kurtosis ان اقدامات کو پرنٹ کرے گا جو وہ اندرونی طور پر لے رہا ہے کیونکہ یہ ہدایات کی تشریح، توثیق، اور پھر ان پر عمل درآمد کرنے کا کام کرتا ہے۔ آخر میں، یہ اپنے بنائے گئے انکلیو (enclave) کا خلاصہ پرنٹ کرتا ہے۔ خلاصے میں **فائلز آرٹفیکٹس** کی فہرست اور **صارف کی خدمات** کی فہرست شامل ہے۔ ڈیفالٹ کنفیگریشن کے ساتھ، صارف کی خدمات میں ایک واحد نوڈ شامل ہے:

- `el-1-geth-lighthouse`، `geth` ایگزیکیوشن کلائنٹ
- `cl-1-lighthouse-geth`، `lighthouse` بیکن نوڈ
- `vc-1-geth-lighthouse`، `lighthouse` توثیق کار کلائنٹ

ہر سروس ان پورٹس کے ساتھ درج ہوتی ہے جنہیں یہ ظاہر کرتی ہے اور وہ مقامی پورٹ جس پر ہر ایک کو میپ کیا گیا ہے۔ مثال کے طور پر، `el-1-geth-lighthouse` سروس کی `rpc` پورٹ وہ جے سن آر پی سی اینڈ پوائنٹ ہے جسے آپ کے dapp ٹولز استعمال کریں گے۔ آپ کی مشین پر درست خدمات اور پورٹ نمبر مختلف ہوں گے۔

آپ کسی بھی وقت یہ چلا کر اس خلاصے کو دوبارہ دیکھ سکتے ہیں:

```sh
kurtosis enclave inspect local-eth-testnet
```

مبارک ہو! آپ نے Docker پر ایک CL (`lighthouse`) اور EL کلائنٹ (`geth`) کے ساتھ ایک مقامی ایتھیریم آزمائشی نیٹ ورک شروع کرنے کے لیے Kurtosis کا استعمال کیا۔

### جائزہ {#review-instantiate-testnet}

اس سیکشن میں، آپ نے ایک کمانڈ چلائی جس نے Kurtosis کو ہدایت کی کہ وہ Kurtosis [Enclave](https://docs.kurtosis.com/advanced-concepts/enclaves/) کے اندر ایک مقامی ایتھیریم آزمائشی نیٹ ورک شروع کرنے کے لیے [GitHub پر دور دراز سے ہوسٹ کیے گئے `ethereum-package`](https://github.com/ethpandaops/ethereum-package) کا استعمال کرے۔ آپ کے انکلیو کے اندر، آپ کو "فائلز آرٹفیکٹس" اور "صارف کی خدمات" دونوں ملیں گے۔

آپ کے انکلیو میں موجود [فائلز آرٹفیکٹس](https://docs.kurtosis.com/advanced-concepts/files-artifacts/) میں وہ تمام ڈیٹا شامل ہے جو EL اور CL کلائنٹس کو بوٹ اسٹریپ کرنے کے لیے تیار اور استعمال کیا گیا ہے، جیسے کہ جینیسس فائلز اور توثیق کار کیز۔ جینیسس ڈیٹا [ethereum-genesis-generator](https://github.com/ethpandaops/ethereum-genesis-generator) کا استعمال کرتے ہوئے بنایا گیا تھا۔

صارف کی خدمات آپ کے انکلیو میں کام کرنے والی تمام کنٹینرائزڈ خدمات کو ظاہر کرتی ہیں۔ آپ دیکھیں گے کہ ایک واحد نوڈ، جس میں EL کلائنٹ اور CL کلائنٹ دونوں شامل ہیں، بنایا گیا ہے۔

## اپنے dapp ڈیولپمنٹ ماحول کو مقامی ایتھیریم آزمائشی نیٹ ورک سے جوڑیں {#connect-your-dapp}

### dapp ڈیولپمنٹ ماحول کو ترتیب دیں {#set-up-dapp-env}

اب جب کہ آپ کے پاس ایک چلتا ہوا مقامی آزمائشی نیٹ ورک ہے، آپ اپنے مقامی آزمائشی نیٹ ورک کو استعمال کرنے کے لیے اپنے dapp ڈیولپمنٹ ماحول کو جوڑ سکتے ہیں۔ اس گائیڈ میں آپ کے مقامی آزمائشی نیٹ ورک پر ایک بلیک جیک dapp کو تعینات کرنے کے لیے Hardhat فریم ورک کا استعمال کیا جائے گا۔

اپنے dapp ڈیولپمنٹ ماحول کو ترتیب دینے کے لیے، اس ریپوزٹری کو کلون کریں جس میں ہماری نمونہ dapp شامل ہے اور اس کی انحصاریاں (dependencies) انسٹال کریں، چلائیں:

```sh
git clone https://github.com/kurtosis-tech/awesome-kurtosis.git
cd awesome-kurtosis/smart-contract-example
npm install --legacy-peer-deps
```

`--legacy-peer-deps` فلیگ کی ضرورت ہے کیونکہ نمونہ پروجیکٹ کے کچھ Hardhat پلگ انز متصادم پیئر انحصاری ورژنز کا اعلان کرتے ہیں۔

یہاں استعمال ہونے والے [smart-contract-example](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example) فولڈر میں [Hardhat](https://hardhat.org/) فریم ورک استعمال کرنے والے dapp ڈیولپر کے لیے عام سیٹ اپ شامل ہے:

- [`contracts/`](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example/contracts) میں بلیک جیک dapp کے لیے چند سادہ سمارٹ کنٹریکٹس شامل ہیں
- [`scripts/`](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example/scripts) میں آپ کے مقامی ایتھیریم نیٹ ورک پر ٹوکن کنٹریکٹ تعینات کرنے کے لیے ایک اسکرپٹ شامل ہے
- [`test/`](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example/test) میں آپ کے ٹوکن کنٹریکٹ کے لیے ایک سادہ .js ٹیسٹ شامل ہے تاکہ اس بات کی تصدیق کی جا سکے کہ ہماری بلیک جیک dapp میں ہر کھلاڑی کے لیے <span dir="ltr">1000</span> ٹوکن منٹ کیے گئے ہیں
- [`hardhat.config.ts`](https://github.com/kurtosis-tech/awesome-kurtosis/blob/main/smart-contract-example/hardhat.config.ts) آپ کے Hardhat سیٹ اپ کو کنفیگر کرتا ہے

### مقامی آزمائشی نیٹ ورک استعمال کرنے کے لیے Hardhat کو کنفیگر کریں {#configure-hardhat}

اپنے dapp ڈیولپمنٹ ماحول کے سیٹ اپ کے ساتھ، اب آپ Kurtosis کا استعمال کرتے ہوئے تیار کردہ مقامی ایتھیریم آزمائشی نیٹ ورک کو استعمال کرنے کے لیے Hardhat کو جوڑیں گے۔ سب سے پہلے، ایگزیکیوشن کلائنٹ کے جے سن آر پی سی اینڈ پوائنٹ کا مقامی پتہ تلاش کریں:

```sh
kurtosis port print local-eth-testnet el-1-geth-lighthouse rpc
```

آؤٹ پٹ ایک URL ہے جیسے `http://127.0.0.1:32769`۔ آپ کی پورٹ مختلف ہوگی۔ اپنی `hardhat.config.ts` کنفیگریشن فائل میں `localnet` اسٹرکٹ میں `<PORT>` کو اس پورٹ سے تبدیل کریں۔

`hardhat.config.ts` میں مثال:

```js
localnet: {
  url: 'http://127.0.0.1:<PORT>',//TODO: <PORT> کو ETH نیٹ ورک Kurtosis پیکیج کے ذریعے تیار کردہ نوڈ URI کے پورٹ سے تبدیل کریں
  // یہ eth-network-package کے ذریعے بنائے گئے پہلے سے فنڈڈ ٹیسٹ اکاؤنٹس سے وابستہ نجی کنجیاں ہیں
  //https://github.com/ethpandaops/ethereum-package/blob/main/src/prelaunch_data_generator/genesis_constants/genesis_constants.star
  accounts: [
    "bcdf20249abf0ed6d944c0288fad489e33f66b3960d9e6229c1cd214ed3bbe31",
    "53321db7c1e331d93a11a41d16f004d7ff63972ec8ec7c25db329728ceeb1710",
    "ab63b23eb7941c1251757e24b3d2350d2bc05c3c388d06f8fe6feafefb1e8c70",
    "5d2344259f42259f82d2c140aa66102ba89b57b4883ee441a8b312622bd42491",
    "27515f805127bebad2fb9b183508bdacb8c763da16f54e0678b16e8f28ef3fff",
    "7ff1a4c1d57e5e784d327c4c7651e952350bc271f156afb3d00d20f5ef924856",
  ],
},
```

یہ نجی کیز عوامی طور پر معلوم ٹیسٹ کیز ہیں۔ انہیں کبھی بھی مین نیٹ یا کسی عوامی نیٹ ورک پر استعمال نہ کریں۔

ایک بار جب آپ اپنی فائل کو محفوظ کر لیتے ہیں، تو آپ کا Hardhat dapp ڈیولپمنٹ ماحول اب آپ کے مقامی ایتھیریم آزمائشی نیٹ ورک سے جڑ گیا ہے! آپ یہ چلا کر تصدیق کر سکتے ہیں کہ آپ کا آزمائشی نیٹ ورک کام کر رہا ہے:

```sh
npx hardhat balances --network localnet
```

آؤٹ پٹ اوپر دیے گئے ہر اکاؤنٹ کا پتہ اور بیلنس درج کرتا ہے۔ مثال کے طور پر، پہلی لائن اس طرح دکھنی چاہیے:

```
0x8943545177806ED17B9F23F0a21ee5948eCaa776 has balance <a large balance>
```

یہ اس بات کی تصدیق کرتا ہے کہ Hardhat آپ کا مقامی آزمائشی نیٹ ورک استعمال کر رہا ہے اور `ethereum-package` کے ذریعے بنائے گئے پہلے سے فنڈڈ اکاؤنٹس کا پتہ لگاتا ہے۔

### مقامی طور پر اپنی dapp کو تعینات اور ٹیسٹ کریں {#deploy-and-test-dapp}

dapp ڈیولپمنٹ ماحول کے مقامی ایتھیریم آزمائشی نیٹ ورک سے مکمل طور پر جڑ جانے کے بعد، اب آپ مقامی آزمائشی نیٹ ورک کا استعمال کرتے ہوئے اپنی dapp کے خلاف ڈیولپمنٹ اور ٹیسٹنگ ورک فلو چلا سکتے ہیں۔

مقامی پروٹو ٹائپنگ اور ڈیولپمنٹ کے لیے `ChipToken.sol` سمارٹ کنٹریکٹ کو مرتب اور تعینات کرنے کے لیے، چلائیں:

```sh
npx hardhat compile
npx hardhat run scripts/deploy.ts --network localnet
```

آؤٹ پٹ کچھ اس طرح دکھنا چاہیے:

```
ChipToken deployed to: 0xAb2A01BC351770D09611Ac80f1DE076D56E0487d
```

اب اپنی مقامی dapp کے خلاف `ChipToken.js` ٹیسٹ چلانے کی کوشش کریں تاکہ اس بات کی تصدیق کی جا سکے کہ ہماری بلیک جیک dapp میں ہر کھلاڑی کے لیے <span dir="ltr">1000</span> ٹوکن منٹ کیے گئے ہیں۔ نمونہ ٹیسٹ اب بھی ethers v5 `deployed()` فنکشن استعمال کرتا ہے، جسے ethers v6 نے `waitForDeployment()` سے بدل دیا ہے، لہذا پہلے اسے اپ ڈیٹ کریں:

```sh
sed -i.bak 's/\.deployed()/.waitForDeployment()/' test/ChipToken.js
```

پھر ٹیسٹ چلائیں:

```sh
npx hardhat test --network localnet
```

آؤٹ پٹ کچھ اس طرح دکھنا چاہیے:

```
ChipToken
    mint
      ✔ should mint 1000 chips for PLAYER ONE

  1 passing (654ms)
```

### جائزہ {#review-dapp-workflows}

اس مقام پر، اب آپ نے ایک dapp ڈیولپمنٹ ماحول ترتیب دے لیا ہے، اسے Kurtosis کے ذریعے بنائے گئے مقامی ایتھیریم نیٹ ورک سے جوڑ دیا ہے، اور اپنی dapp کے خلاف ایک سادہ ٹیسٹ مرتب، تعینات، اور چلا لیا ہے۔

اب آئیے دریافت کرتے ہیں کہ آپ مختلف نیٹ ورک کنفیگریشنز کے تحت ہماری dapps کی ٹیسٹنگ کے لیے بنیادی نیٹ ورک کو کیسے کنفیگر کر سکتے ہیں۔

## مقامی ایتھیریم آزمائشی نیٹ ورک کو کنفیگر کرنا {#configure-testnet}

### کلائنٹ کنفیگریشنز اور نوڈز کی تعداد کو تبدیل کرنا {#configure-client-config-and-num-nodes}

آپ کے مقامی ایتھیریم آزمائشی نیٹ ورک کو مختلف EL اور CL کلائنٹ جوڑیوں کے ساتھ ساتھ نوڈز کی مختلف تعداد استعمال کرنے کے لیے کنفیگر کیا جا سکتا ہے، جو اس منظر نامے اور مخصوص نیٹ ورک کنفیگریشن پر منحصر ہے جسے آپ تیار یا ٹیسٹ کرنا چاہتے ہیں۔ اس کا مطلب یہ ہے کہ، ایک بار سیٹ اپ ہونے کے بعد، آپ ایک حسب ضرورت مقامی آزمائشی نیٹ ورک شروع کر سکتے ہیں اور اسے مختلف نیٹ ورک کنفیگریشنز کے تحت انہی ورک فلوز (تعیناتی، ٹیسٹ وغیرہ) کو چلانے کے لیے استعمال کر سکتے ہیں تاکہ یہ یقینی بنایا جا سکے کہ سب کچھ توقع کے مطابق کام کر رہا ہے۔ ان دیگر پیرامیٹرز کے بارے میں مزید جاننے کے لیے جنہیں آپ تبدیل کر سکتے ہیں، [`ethereum-package` کنفیگریشن دستاویزات](https://github.com/ethpandaops/ethereum-package#configuration) دیکھیں۔

اسے آزمائیں! آپ YAML فائل کے ذریعے `ethereum-package` کو مختلف کنفیگریشن آپشنز پاس کر سکتے ہیں۔ یہ نیٹ ورک پیرامیٹرز فائل وہ مخصوص کنفیگریشنز فراہم کرتی ہے جنہیں Kurtosis مقامی ایتھیریم نیٹ ورک کو ترتیب دینے کے لیے استعمال کرے گا۔

`network_params.yaml` نامی ایک فائل بنائیں جو مختلف EL/CL جوڑیوں کے ساتھ تین نوڈز شروع کرتی ہے:

- `geth`/`lighthouse` کے ساتھ نوڈ 1
- `geth`/`lodestar` کے ساتھ نوڈ 2
- `geth`/`teku` کے ساتھ نوڈ 3

یہ کنفیگریشن آپ کی dapp کی ٹیسٹنگ کے لیے ایتھیریم نوڈ کے نفاذ کا ایک متضاد (heterogeneous) نیٹ ورک بناتی ہے۔ آپ کی کنفیگریشن فائل اس طرح دکھنی چاہیے:

```yaml
participants:
  - el_type: geth
    cl_type: lighthouse
  - el_type: geth
    cl_type: lodestar
  - el_type: geth
    cl_type: teku
network_params:
  seconds_per_slot: 12
```

`participants` میں ہر اندراج نیٹ ورک میں ایک نوڈ سے میپ ہوتا ہے، لہذا <span dir="ltr">3</span> `participants` اندراجات Kurtosis کو آپ کے نیٹ ورک میں <span dir="ltr">3</span> نوڈز شروع کرنے کے لیے کہیں گے۔ ہر اندراج آپ کو اس مخصوص نوڈ کے لیے استعمال ہونے والی EL اور CL جوڑی کی وضاحت کرنے کی اجازت دیتا ہے۔ کوئی بھی پیرامیٹرز جن کی آپ وضاحت نہیں کرتے ہیں وہ اپنی ڈیفالٹ اقدار کو برقرار رکھتے ہیں۔

`network_params` اسٹرکٹ ان نیٹ ورک سیٹنگز کو کنفیگر کرتا ہے جو ہر نوڈ کے لیے جینیسس فائلز بنانے کے لیے استعمال ہوتی ہیں اور ساتھ ہی دیگر سیٹنگز جیسے نیٹ ورک کے سیکنڈز فی سلاٹ۔

اپنی پیرامیٹرز فائل کو محفوظ کریں اور پھر اسے چلا کر اپنا Kurtosis پیکیج چلانے کے لیے استعمال کریں:

```sh
kurtosis clean -a && kurtosis run --enclave local-eth-testnet github.com/ethpandaops/ethereum-package --args-file ./network_params.yaml
```

نوٹ: `kurtosis clean -a` کمانڈ یہاں Kurtosis کو نیا شروع کرنے سے پہلے پرانے آزمائشی نیٹ ورک اور اس کے مواد کو تباہ کرنے کی ہدایت دینے کے لیے استعمال کی گئی ہے۔

ایک بار پھر، Kurtosis تھوڑی دیر کے لیے کام کرے گا اور انفرادی اقدامات کو پرنٹ کرے گا جو ہو رہے ہیں۔ بالآخر، یہ انکلیو کا خلاصہ پرنٹ کرتا ہے۔ اس بار، صارف کی خدمات میں تین نوڈز شامل ہیں، مثال کے طور پر ایگزیکیوشن کلائنٹس کے لیے `el-1-geth-lighthouse`، `el-2-geth-lodestar`، اور `el-3-geth-teku`، اس کے ساتھ مماثل اتفاق رائے اور توثیق کار کلائنٹس۔

مبارک ہو! آپ نے کامیابی کے ساتھ اپنے مقامی آزمائشی نیٹ ورک کو <span dir="ltr">1</span> کے بجائے <span dir="ltr">3</span> نوڈز رکھنے کے لیے کنفیگر کر لیا ہے۔ اپنی dapp کے خلاف وہی ورک فلوز چلانے کے لیے جو آپ نے پہلے کیے تھے (تعینات اور ٹیسٹ)، اپنی `hardhat.config.ts` کنفیگریشن فائل میں `localnet` اسٹرکٹ میں `<PORT>` کو اپنے نئے، <span dir="ltr">3</span>-نوڈ مقامی آزمائشی نیٹ ورک میں کسی بھی `el-<num>-...` سروس کی `rpc` پورٹ سے تبدیل کر کے وہی کام انجام دیں جو ہم نے پہلے کیے تھے۔

## نتیجہ {#conclusion}

اور بس! اس مختصر گائیڈ کا خلاصہ کرنے کے لیے، آپ نے:

- Kurtosis کا استعمال کرتے ہوئے Docker پر ایک مقامی ایتھیریم آزمائشی نیٹ ورک بنایا
- اپنے مقامی dapp ڈیولپمنٹ ماحول کو مقامی ایتھیریم نیٹ ورک سے جوڑا
- مقامی ایتھیریم نیٹ ورک پر ایک dapp تعینات کی اور اس کے خلاف ایک سادہ ٹیسٹ چلایا
- بنیادی ایتھیریم نیٹ ورک کو <span dir="ltr">3</span> نوڈز رکھنے کے لیے کنفیگر کیا

ہم آپ سے یہ سننا پسند کریں گے کہ آپ کے لیے کیا اچھا رہا، کیا بہتر کیا جا سکتا ہے، یا آپ کے کسی بھی سوال کا جواب دینا چاہیں گے۔ [GitHub](https://github.com/kurtosis-tech/kurtosis/issues/new/choose) کے ذریعے رابطہ کرنے میں ہچکچاہٹ محسوس نہ کریں!
