பெரும்பாலான முக்கிய எத்திரியம் சுரண்டல்கள் அதே இறுதிப் படியைக் கொண்டிருந்தன: ஒரு பயனர் தங்களால் அர்த்தமுள்ள வகையில் புரிந்துகொள்ள முடியாத ஒரு பரிவர்த்தனைக்கு ஒப்புதல் அளிப்பது. வன்பொருள் பணப்பைகள் மூல ஹெக்ஸ் அழைப்புத் தரவைக் காட்டுகின்றன, மேலும் மோசமான விஷயம் என்னவென்றால், குருட்டுத்தனமாகக் கையொப்பமிடுதலை (blind signing) இயக்கியிருக்க உங்களை வற்புறுத்துகின்றன. மென்பொருள் பணப்பைகள் குறிவிலக்கப்பட்ட புலங்களைக் காட்டுகின்றன, ஆனால் அவை ஒப்பந்தத்தை அங்கீகரிக்கும் போது மட்டுமே. நெறிமுறை புதியதாக இருப்பதாலோ, பயன்பாடு சமரசம் செய்யப்பட்டதாலோ அல்லது சாதனம் ஆஃப்லைனில் இருப்பதாலோ, அவை அங்கீகரிக்காதபோது, பயனர்கள் குருட்டுத்தனமாகக் கையொப்பமிடுகிறார்கள்.

[ERC-7730](https://eips.ethereum.org/EIPS/eip-7730) உங்கள் ஒப்பந்தத்தின் செயல்பாட்டு அழைப்புகளின் *அர்த்தம்* என்ன என்பதை விவரிப்பதற்கான நிலையான JSON வடிவமைப்பை வரையறுக்கிறது.

ERC-7730 ஐ ஆதரிக்கும் ஒரு பணப்பை உங்கள் விவரிப்பானைப் படித்து இதைக் காட்டுகிறது:

> **பரிமாற்றம்**  
> அனுப்பு: 1,000 USDC  
> குறைந்தபட்சம் பெறு: 0.42 WETH  
> நெறிமுறை: Uniswap V2

அல்லது மனிதர்கள் மற்றும் முகவர்கள் இருவராலும் படிக்கக்கூடிய வகையில் கட்டமைக்கப்பட்ட ஒற்றை வாக்கியம்:

> குறைந்தபட்சம் 0.42 WETH-க்கு 1,000 USDC-ஐப் பரிமாற்றம் செய்

ஒரு செயல்பாட்டுத் தேர்வி மற்றும் மூல முழு எண் மதிப்புகளின் பட்டியலுக்குப் பதிலாக.

இதுதான் [தெளிவான கையொப்பமிடுதல்](https://clearsigning.org/) — "நீங்கள் பார்ப்பதையே நீங்கள் கையொப்பமிடுகிறீர்கள்." உங்கள் சொந்த ஒப்பந்தத்திற்கான விவரிப்பானை எழுதுவது, அதிகாரப்பூர்வ CLI கருவி மூலம் அதைச் சரிபார்ப்பது மற்றும் திறந்த பதிவேட்டில் அதைச் சமர்ப்பிப்பது போன்றவற்றின் மூலம் இந்தப் பயிற்சி உங்களை வழிநடத்துகிறது.

## முன்நிபந்தனைகள் {#prerequisites}

- Solidity மற்றும் திறன் ஒப்பந்த ABI-கள் பற்றிய பரிச்சயம்
- சரிபார்க்கப்பட்ட ABI உடன் நிலைநிறுத்தப்பட்ட திறன் ஒப்பந்தம் (ஒரு விவரிப்பான் பதிவேட்டில் ஏற்கப்படுவதற்கு முன்பு [Sourcify](https://sourcify.dev) சரிபார்ப்பு தேவை)
- சரிபார்ப்பு CLI-க்கு Python 3.12 (பொருத்தப்பட்ட `erc7730` தொகுப்பு Python 3.13 அல்லது அதற்குப் பிந்தைய பதிப்புகளில் நிறுவப்படாது). உங்கள் கணினியின் Python வேறு பதிப்பாக இருந்தால், [uv](https://docs.astral.sh/uv/) உங்களுக்காக Python 3.12 ஐப் பதிவிறக்கி இயக்க முடியும்
- அடிப்படை JSON அறிவு

## ERC-7730 விவரிப்பான் என்றால் என்ன? {#what-is-an-erc-7730-descriptor}

விவரிப்பான் என்பது மூன்று பிரிவுகளைக் கொண்ட ஒற்றை JSON கோப்பாகும்:

| பிரிவு | நோக்கம் |
| :---- | :---- |
| `context` | சங்கிலி ID மற்றும் முகவரி மூலம் குறிப்பிட்ட ஒப்பந்த நிலைநிறுத்தங்களுடன் விவரிப்பானைப் பிணைக்கிறது |
| `metadata` | திட்டத்திற்குப் பெயரிடுகிறது மற்றும் மீண்டும் பயன்படுத்தக்கூடிய மாறிலிகளை வரையறுக்கிறது |
| `display` | ஒவ்வொரு செயல்பாட்டுக் கையொப்பத்தையும் மனிதர்கள் படிக்கக்கூடிய லேபிள்கள் மற்றும் புல வடிவங்களுடன் வரைபடமாக்குகிறது |

விவரிப்பான் ஒப்பந்தத்திலிருந்து தனித்தனியாக இருப்பதால், மறுநிலைநிறுத்தம் செய்யாமலேயே எந்தவொரு தற்போதைய நெறிமுறைக்கும் தெளிவான கையொப்பமிடுதல் ஆதரவை நீங்கள் சேர்க்கலாம். பணப்பைகள் பதிவேட்டிலிருந்து விவரிப்பான்களை மீட்டெடுத்து, கையொப்பமிடும் நேரத்தில் அவற்றைப் பயன்படுத்துகின்றன.

## படி 1: கோப்புச் சட்டகத்தை உருவாக்கவும் {#step-1-create-the-file-skeleton}

`calldata-<ContractName>.json` என்ற பெயரில் ஒரு கோப்பை உருவாக்கவும், எடுத்துக்காட்டாக `calldata-SwapRouter.json`. தட்டச்சு செய்யப்பட்ட தரவுச் செய்திகளுக்கான `eip712-` என்பதற்கு மாறாக, இந்த விவரிப்பான் ஒப்பந்தச் செயல்பாட்டு அழைப்புகளை உள்ளடக்கியது என்பதை `calldata-` முன்னொட்டு பதிவேட்டிற்குக் கூறுகிறது. நீங்கள் ஒரு ஒப்பந்தத்தின் பல பதிப்புகளை விவரிக்க வேண்டும் என்றால், பதிவேட்டின் `calldata-UniswapV3Router02.json` இல் உள்ளதைப் போல, பெயரில் ஒப்பந்தப் பதிப்பைச் சேர்க்கவும்.

```json
{
  "$schema": "https://eips.ethereum.org/assets/eip-7730/erc7730-v2.schema.json",
  "context": {},
  "metadata": {},
  "display": {
    "formats": {}
  }
}
```

## படி 2: சூழல் பிரிவை எழுதவும் {#step-2-write-the-context-section}

`context` பிரிவு விவரிப்பானை ஒன்று அல்லது அதற்கு மேற்பட்ட ஒப்பந்த நிலைநிறுத்தங்களுடன் பிணைக்கிறது. உள்வரும் பரிவர்த்தனையைச் சரியான விவரிப்பானுடன் பொருத்த பணப்பைகள் இதைப் பயன்படுத்துகின்றன.

```json
"context": {
  "$id": "example-swap-router",
  "contract": {
    "deployments": [
      { "chainId": 1, "address": "0xYourContractAddressOnMainnet" },
      { "chainId": 137, "address": "0xYourContractAddressOnPolygon" }
    ]
  }
}
```

### சூழல் புலங்கள் {#context-fields}

- `context.$id` — இந்த விவரிப்பான் ஆவணம் அல்லது நிலைநிறுத்த உள்ளமைவிற்கான தனித்துவமான அடையாளங்காட்டி.
- `contract.deployments` — இந்த விவரிப்பான் பொருந்தும் நிலைநிறுத்தங்களின் தொகுப்பு.
- `deployments[].chainId` — ஒரு நிலைநிறுத்தத்திற்கான EVM சங்கிலி ID. உங்கள் ஒப்பந்தம் நிலைநிறுத்தப்பட்டுள்ள ஒவ்வொரு சங்கிலியையும் சேர்க்கவும்.
- `deployments[].address` — பணப்பைகள் இந்த விவரிப்பானுடன் தொடர்புபடுத்த வேண்டிய ஒப்பந்த முகவரி. பயனர்கள் உண்மையில் பரிவர்த்தனைகளை அனுப்பும் முகவரி இதுதான். உங்கள் ஒப்பந்தம் மேம்படுத்தக்கூடியதாக இருந்தால், அது ப்ராக்ஸி முகவரியாகும், செயல்படுத்தல் முகவரி அல்ல, அதே சமயம் `display.formats` இல் உள்ள செயல்பாட்டுக் கையொப்பங்கள் செயல்படுத்தலின் ABI-யிலிருந்து வருகின்றன.

## படி 3: மீத்தரவுப் பிரிவை எழுதவும் {#step-3-write-the-metadata-section}

இந்தக் கோப்பால் விவரிக்கப்பட்ட திட்டம் மற்றும் ஒப்பந்தம் பற்றிய மனிதர்கள் படிக்கக்கூடிய தகவலை மீத்தரவுப் பிரிவு வழங்குகிறது. கையொப்பமிடும் போது நெறிமுறைப் பெயர்கள், இணைப்புகள் மற்றும் பிற சூழல் விவரங்களைக் காண்பிக்க பணப்பைகள் இந்தத் தகவலைப் பயன்படுத்தலாம்.

```json
"metadata": {
  "owner": "Example Swap Protocol",
  "info": { "url": "https://example.xyz" },
  "contractName": "SwapRouter"
}
```

### மீத்தரவுப் புலங்கள் {#metadata-fields}

- `owner` — இந்த விவரிப்பானுக்குப் பொறுப்பான திட்டம், நெறிமுறை, நிறுவனம் அல்லது பராமரிப்பாளர்.
- `info.url` — கூடுதல் சூழலுக்காகப் பயனர்களுக்குப் பணப்பைகள் காண்பிக்கக்கூடிய அதிகாரப்பூர்வத் திட்டம் அல்லது ஆவண URL.
- `contractName` — இந்தக் கோப்பால் விவரிக்கப்பட்ட ஒப்பந்தம் அல்லது செயலாக்கப் பெயர், பொதுவாகச் சரிபார்க்கப்பட்ட மூலக் குறியீடு அல்லது ABI-யுடன் பொருந்தும்.

உங்கள் ERC-7730 கோப்பு ஒரு ERC-20 ஒப்பந்தத்தை விவரித்தால், நீங்கள் ஒரு வில்லைப் பொருளையும் சேர்க்க வேண்டும். 

## படி 4: காட்சி வடிவங்கள் பிரிவை எழுதவும் {#step-4-write-the-displayformats-section}

`display.formats` பொருள் செயல்பாட்டுக் கையொப்பங்களை மனிதர்கள் படிக்கக்கூடிய கையொப்பமிடும் வழிமுறைகளுடன் வரைபடமாக்குகிறது. பயனர்கள் ஒரு பரிவர்த்தனைக்கு ஒப்புதல் அளிப்பதற்கு முன்பு பணப்பைகள் உங்கள் செயல்பாட்டை அவர்களுக்கு எப்படிக் காட்டுகின்றன என்பது இதுதான்!

ஒவ்வொரு திறவுகோலும் மனிதர்கள் படிக்கக்கூடிய ABI துணுக்காகும் — அளவுருப் பெயர்கள் மற்றும் அளவுரு வகைகள் இரண்டும் உங்கள் ABI-யில் தோன்றுவது போலவே உள்ள செயல்பாட்டுக் கையொப்பம்.

இந்த எடுத்துக்காட்டு Uniswap V2 `Router02` ஒப்பந்தத்திலிருந்து `swapExactTokensForTokens` ஐ விவரிக்கிறது. உள்ளீட்டு வில்லை என்பது `path` இன் முதல் உறுப்பு, மற்றும் வெளியீட்டு வில்லை என்பது கடைசி உறுப்பு (பல-தாவல் பரிமாற்றத்திற்கு `path` இரண்டிற்கும் மேற்பட்ட உறுப்புகளைக் கொண்டிருக்கலாம்).

```json
"display": {
  "formats": {
    "swapExactTokensForTokens(uint256 amountIn,uint256 amountOutMin,address[] path,address to,uint256 deadline)": {
      "intent": "Swap",
      "interpolatedIntent": "Swap {amountIn} for at least {amountOutMin}",
      "fields": [
        {
          "path": "#.amountIn",
          "label": "Send",
          "format": "tokenAmount",
          "params": {
            "tokenPath": "#.path.[0]"
          }
        },
        {
          "path": "#.amountOutMin",
          "label": "Receive minimum",
          "format": "tokenAmount",
          "params": {
            "tokenPath": "#.path.[-1]"
          }
        },
        {
          "path": "#.to",
          "label": "Recipient",
          "format": "addressName",
          "params": {
            "types": ["eoa", "contract"],
            "sources": ["local", "ens"]
          }
        },
        {
          "path": "#.deadline",
          "label": "Expires",
          "format": "date",
          "params": {
            "encoding": "timestamp"
          }
        }
      ]
    }
  }
}
```

### காட்சிப் புலங்கள் {#display-fields}

- **`intent`** — **(தேவை)** "பரிமாற்றம்" போன்ற செயலின் சுருக்கமான, பயனர் நட்பு விளக்கம்.
- **`interpolatedIntent`** — **(பரிந்துரைக்கப்படுகிறது)** `"Swap {amountIn} for at least {amountOutMin}"` போன்ற வடிவமைக்கப்பட்ட புல மதிப்புகளை உட்பொதிக்கும் ஒரு செழுமையான வாக்கிய வார்ப்புரு. எந்தவொரு காட்சிக் கட்டுப்பாடுகளும் வழங்கப்பட்டால் பணப்பைகள் காட்டத் தேர்வுசெய்யக்கூடிய இன்னும் அதிக பயனர் நட்பு விவரிப்பானை வழங்க `intent` உடன் இதைச் சேர்க்கவும்.
- **`fields`** — **(தேவை)** பணப்பைகள் பயனர்களுக்குக் காட்ட வேண்டிய பரிவர்த்தனைப் புலங்களின் வரிசைப்படுத்தப்பட்ட பட்டியல்.
  - **`path`** — **(தேவை)** பரிவர்த்தனைத் தரவிற்கான குறிப்பு. `#.fieldName` என்பது ABI-யில் உள்ள பெயரின் மூலம் குறிவிலக்கப்பட்ட அழைப்புத் தரவு அளவுருவைக் குறிக்கிறது. `@.value` என்பது பரிவர்த்தனையுடன் அனுப்பப்பட்ட ETH மதிப்பைக் குறிக்கிறது. அணிவரிசை உறுப்புகள் அடைப்புக்குறிக்கு முன் `.` உடன் எழுதப்படுகின்றன: `#.path.[0]` என்பது முதல் உறுப்பு மற்றும் `#.path.[-1]` என்பது கடைசி உறுப்பு. `#.path[0]` (புள்ளி இல்லாமல்) லிண்டரால் நிராகரிக்கப்படுகிறது.
  - **`label`** — **(தேவை)** மதிப்பிற்கு அருகில் காட்டப்படும் மனிதர்கள் படிக்கக்கூடிய லேபிள்.
  - **`format`** — **(பரிந்துரைக்கப்படுகிறது)** மதிப்பு எவ்வாறு வழங்கப்பட வேண்டும் என்பதைக் கட்டுப்படுத்துகிறது. பொதுவான வடிவங்கள் பின்வருமாறு:
    - `tokenAmount`
    - `addressName`
    - `date`

    கூடுதல் வடிவமைப்பு தேவைப்படாதபோது `raw` ஐப் பயன்படுத்தவும். சில வடிவங்கள் கூடுதல் **`params`** உள்ளமைவை ஏற்கின்றன. எடுத்துக்காட்டாக:

    - எந்த வில்லை முகவரி தசமங்கள் மற்றும் டிக்கர் மீத்தரவை வழங்குகிறது என்பதை அடையாளம் காண `tokenAmount` ஆனது `tokenPath` ஐப் பயன்படுத்தலாம்.
    - நேரமுத்திரை எவ்வாறு குறியாக்கம் செய்யப்படுகிறது என்பதை விவரிக்க `date` ஆனது `encoding` ஐப் பயன்படுத்தலாம்.

    தேர்ந்தெடுக்கப்பட்ட வடிவத்திற்கு கூடுதல் தகவல் தேவையில்லை என்றால், `params` ஐத் தவிர்க்கவும்.

## படி 5: பதிவேட்டில் சமர்ப்பிக்கவும் {#step-5-submit-to-the-registry}

[ERC-7730 பதிவேடு](https://github.com/ethereum/clear-signing-erc7730-registry) என்பது ஒரு நடுநிலை நிர்வாகியாக [எத்தீரியம் அறக்கட்டளை](/foundation/) வழங்கும் திறந்த களஞ்சியமாகும். யார் வேண்டுமானாலும் அதைக் குளோன் செய்து சுய-ஹோஸ்ட் செய்யச் சுதந்திரம் உண்டு — பணப்பைகள் எந்தப் பதிவேட்டு நிகழ்வுகளை நம்புகின்றன என்பதைச் சுயாதீனமாக முடிவு செய்கின்றன.

1. GitHub-இல் களஞ்சியத்தைக் கவை செய்யவும்
2. `registry/<your-project-name>/` இல் ஒரு கோப்புறையை உருவாக்கவும்
3. உங்கள் கோப்பை அதற்குள் வைக்கவும்: `registry/myproject/calldata-SwapRouter.json`
4. களஞ்சியத்திற்குள் பயன்படுத்தப்படும் தொடர்புடைய பாதைக்கு `$schema` புலத்தைப் புதுப்பிக்கவும்: `"../../specs/erc7730-v2.schema.json"`. CI இங்கே ஒரு URL-ஐ நிராகரிக்கிறது.
5. ஒரு சோதனைக் கோப்பைச் சேர்க்கவும் (கீழே காண்க)
6. உங்கள் கோப்புகளை உள்ளூரில் சரிபார்க்கவும் (கீழே காண்க)
7. ஒரு இழுப்பு கோரிக்கையை (pull request) திறக்கவும். ஒவ்வொரு இழுப்பு கோரிக்கையும் `registry/` இன் கீழ் ஒரு கோப்புறையை மட்டுமே மாற்ற முடியும்

### ஒரு சோதனைக் கோப்பைச் சேர்க்கவும் {#add-a-test-file}

நீங்கள் சேர்க்கும் அல்லது மாற்றும் ஒவ்வொரு விவரிப்பானுக்கும் ஒரு சோதனைக் கோப்பு தேவை, எனவே தெளிவான கையொப்பமிடுதல் செயலாக்கங்களை அதற்கு எதிராகச் சரிபார்க்கலாம். `display.formats` இல் உள்ள ஒவ்வொரு செயல்பாட்டிற்கும் குறைந்தது ஒரு சோதனை நிகழ்வுடன் `registry/<your-project-name>/testsv2/calldata-<ContractName>.tests.json` ஐ உருவாக்கவும். CI ஒவ்வொரு வடிவத்தின் செயல்பாட்டுத் தேர்வியைப் பெறுகிறது மற்றும் எந்தச் சோதனைப் பரிவர்த்தனையும் அதை அழைக்கவில்லை என்றால் தோல்வியடையும்.

```json
{
  "$schema": "../../../specs/erc7730-tests-v2.schema.json",
  "descriptor": "../calldata-SwapRouter.json",
  "dataProvider": {
    "tokens": {
      "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48": { "symbol": "USDC", "decimals": 6, "name": "USD Coin" },
      "0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2": { "symbol": "WETH", "decimals": 18, "name": "Wrapped Ether" }
    }
  },
  "tests": [
    {
      "description": "Swap 1,000 USDC for at least 0.42 WETH",
      "rawTx": "0x02f9012f0180843b9aca00...",
      "expected": {
        "intent": "Swap",
        "interpolatedIntent": "Swap 1000 USDC for at least 0.42 WETH",
        "owner": "Example Swap Protocol",
        "fields": [
          { "label": "Send", "value": "1000 USDC" },
          { "label": "Receive minimum", "value": "0.42 WETH" },
          { "label": "Recipient", "value": "0x1234567890123456789012345678901234567890" },
          { "label": "Expires", "value": "2026-01-01 00:00:00Z" }
        ]
      }
    }
  ]
}
```

- `rawTx` என்பது முழுமையாகத் தொடராக்கப்பட்ட **கையொப்பமிடப்படாத** பரிவர்த்தனை (இங்கே சுருக்கப்பட்டுள்ளது), அழைப்புத் தரவு மட்டுமல்ல. உங்கள் ஒப்பந்தத்திற்கான உண்மையான பரிவர்த்தனைகளே சிறந்த சோதனை நிகழ்வுகளாகும்.
- `dataProvider` வில்லை மீத்தரவை வழங்குகிறது (மற்றும் விருப்பமாக முகவரி மற்றும் ENS பெயர்கள்) எனவே சோதனைகளுக்குப் பிணைய அணுகல் தேவையில்லை.
- `expected` என்பது ஒரு பணப்பை காட்ட வேண்டியதாகும். CI ஒவ்வொரு சோதனை நிகழ்வையும் தெளிவான கையொப்பமிடுதல் செயலாக்கங்களுடன் வழங்குகிறது மற்றும் இழுப்பு கோரிக்கையில் ஏதேனும் வேறுபாடுகள் இருந்தால் புகாரளிக்கிறது.

EIP-712 விவரிப்பான்களுக்கான சோதனைக் கோப்புகள் உட்பட முழு வடிவத்திற்கும் பதிவேட்டின் README-இல் உள்ள [குறிப்புச் சோதனை நிகழ்வுகளைக்](https://github.com/ethereum/clear-signing-erc7730-registry#reference-test-cases) காண்க.

### உள்ளூரில் சரிபார்க்கவும் {#validate-locally}

பதிவேடு `.github/requirements.txt` இல் பொருத்தப்பட்ட [`erc7730`](https://github.com/sourcifyeth/python-erc7730) கட்டளை வரி கருவி மூலம் விவரிப்பான்களைச் சரிபார்க்கிறது. Python 3.12 சூழலில், உங்கள் கவையின் மூலத்திலிருந்து (root) அதை இயக்கவும்:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r .github/requirements.txt
erc7730 lint registry/myproject/calldata-SwapRouter.json
```

நீங்கள் [uv](https://docs.astral.sh/uv/) ஐப் பயன்படுத்தினால், மெய்நிகர் சூழலைத் தவிர்க்கலாம், தேவைப்பட்டால் uv Python 3.12 ஐப் பதிவிறக்கும்:

```sh
uvx --python 3.12 --from "$(cat .github/requirements.txt)" erc7730 lint registry/myproject/calldata-SwapRouter.json
```

லிண்டர் திட்டவட்டத்திற்கு (schema) எதிராகவும் உங்கள் ஒப்பந்தத்தின் சரிபார்க்கப்பட்ட ABI-க்கு எதிராகவும் விவரிப்பானைச் சரிபார்க்கிறது. ஒவ்வொரு பிழையையும் சரிசெய்யவும். `Missing display format` போன்ற எச்சரிக்கைகள் உங்கள் விவரிப்பான் இன்னும் விவரிக்காத செயல்பாடுகளை ஒப்பந்தம் கொண்டுள்ளது என்பதைக் குறிக்கின்றன. CI செய்யும் அதே வழியில் `$schema` பாதைகள் மற்றும் சோதனைக் கோப்பையும் சரிபார்க்க, பதிவேட்டின் README-இல் உள்ள [எப்படிச் சரிபார்ப்பது](https://github.com/ethereum/clear-signing-erc7730-registry#how-to-validate) என்பதைக் காண்க.

நீங்கள் PR-ஐத் திறக்கும்போது, CI தானாகவே திட்டவட்டச் சரிபார்ப்பை இயக்குகிறது, செயல்பாட்டுக் கையொப்பங்கள் செல்லுபடியாகும் தேர்வியிகளை உருவாக்குகின்றனவா என்பதைச் சரிபார்க்கிறது, ஒப்பந்த முகவரி Sourcify-இல் சரிபார்க்கப்பட்டதை உறுதிப்படுத்துகிறது மற்றும் ABI முரண்பாடுகளைக் கொடியிடுகிறது. சரிபார்ப்பு முடிவுகள் PR-இல் உள்ளமைவாகத் தோன்றும். பதிவேட்டுப் பராமரிப்பாளர்கள் தவறான அல்லது தீங்கிழைக்கக்கூடிய விவரிப்பான்களுக்கான சமர்ப்பிப்புகளைத் திரையிடுகிறார்கள். பதிவேட்டில் சேர்ப்பது தணிக்கை அல்லது ஒப்புதலைக் குறிக்காது.

## ஒன்றிணைத்த பிறகு என்ன நடக்கும்? {#what-happens-after-merging}

பதிவேட்டில் உள்ள அனைத்து விவரிப்பான்களும் தணிக்கையாளர்களுக்குத் திறந்திருக்கும். உங்கள் PR ஒன்றிணைக்கப்பட்ட பிறகு, எந்தவொரு தணிக்கையாளரும் உங்கள் விவரிப்பானை மதிப்பாய்வு செய்து, அதன் துல்லியத்தை உறுதிப்படுத்தும் ஒரு கிரிப்டோகிராஃபிக் சான்றளிப்பை ([ERC-8176](https://eips.ethereum.org/EIPS/eip-8176) இன் கீழ்) வெளியிடலாம். 

இந்தச் சான்றளிப்பு சமிக்ஞைகள் பணப்பைகள் தங்களின் சொந்த நம்பிக்கைக் கொள்கைகளைப் பயன்படுத்த அனுமதிக்கின்றன — பல சுயாதீனச் சான்றளிப்புகளைக் கொண்ட ஒரு விவரிப்பான், சான்றளிப்பு இல்லாததை விட அதிக மதிப்பைக் கொண்டுள்ளது. [clearsigning.org](https://clearsigning.org) மூலம் நீங்கள் தணிக்கையாளர் சமூகத்தை அணுகலாம்.

பணப்பைகள் எந்தப் பதிவேட்டை ஆதரிக்கும் என்பதைத் தேர்வு செய்கின்றன. உங்கள் விவரிப்பான் பதிவேட்டில் வந்தவுடன், ERC-7730 ஐ ஆதரிக்கும் பணப்பைகள் அது அவற்றின் பதிவேட்டில் இருந்தால் அதைப் பெறத் தொடங்கும், மேலும் பயனர்கள் உங்கள் ஒப்பந்தத்துடன் தொடர்பு கொள்ளும்போது மனிதர்கள் படிக்கக்கூடிய தரவைக் காண்பிக்கும்.
