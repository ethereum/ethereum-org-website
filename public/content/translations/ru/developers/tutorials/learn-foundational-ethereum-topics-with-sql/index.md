Многие руководства по Эфириуму ориентированы на разработчиков, но не хватает образовательных ресурсов для аналитиков данных или для людей, которые хотят просматривать ончейн-данные без запуска клиента или узла.

Это руководство поможет читателям понять фундаментальные концепции Эфириума, включая транзакции, блоки и газ, путем запроса ончейн-данных с помощью языка структурированных запросов (SQL) через интерфейс, предоставляемый [Dune](https://dune.com/). В запросах используется [DuneSQL](https://docs.dune.com/query-engine/overview), диалект SQL от Dune.

Ончейн-данные могут помочь нам понять Эфириум, сеть и экономику вычислительных мощностей, а также должны служить основой для понимания проблем, с которыми Эфириум сталкивается сегодня (например, рост цен на газ), и, что более важно, дискуссий вокруг решений для масштабирования.

### Транзакции {#transactions}

Путь пользователя в Эфириуме начинается с инициализации контролируемого пользователем аккаунта или сущности с балансом ETH. Существует два типа аккаунтов: контролируемые пользователем или смарт-контракты (см. [ethereum.org](/developers/docs/accounts/)).

Любой аккаунт можно просмотреть в обозревателе блоков, таком как [Etherscan](https://etherscan.io/) или [Blockscout](https://eth.blockscout.com/). Обозреватели блоков — это портал к данным Эфириума. Они отображают в режиме реального времени данные о блоках, транзакциях, валидаторах, аккаунтах и другой ончейн-активности (см. [здесь](/developers/docs/data-and-analytics/block-explorers/)).

Однако пользователь может захотеть запросить данные напрямую, чтобы сверить информацию, предоставляемую внешними обозревателями блоков. [Dune](https://dune.com/) предоставляет эту возможность любому, кто обладает некоторыми знаниями SQL.

Для справки, аккаунт смарт-контракта Фонда Ethereum (EF) можно просмотреть на [Blockscout](https://eth.blockscout.com/address/0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe).

Следует отметить, что все аккаунты, включая аккаунт EF, имеют публичный адрес, который можно использовать для отправки и получения транзакций.

Баланс аккаунта на Etherscan состоит из обычных и внутренних транзакций. Внутренние транзакции, несмотря на название, не являются _фактическими_ транзакциями, которые изменяют состояние цепи. Это переводы стоимости, инициированные выполнением контракта ([источник](https://ethereum.stackexchange.com/questions/3417/how-to-get-contract-internal-transactions)). Поскольку внутренние транзакции не имеют подписи, они **не** включаются в блокчейн как транзакции. Dune записывает их отдельно, в таблицу `ethereum.traces`.

Поэтому в этом руководстве основное внимание будет уделено обычным транзакциям. Их можно запросить следующим образом:

```sql
WITH temp_table AS (
SELECT
    hash,
    block_number,
    block_time,
    "from",
    "to",
    value / 1e18 AS ether,
    gas_used,
    gas_price / 1e9 AS gas_price_gwei
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
)
SELECT
    hash,
    block_number,
    block_time,
    "from",
    "to",
    ether,
    (gas_used * gas_price_gwei) / 1e9 AS txn_fee
FROM temp_table
```

Обратите внимание, что адреса записываются как литералы `0x...` без кавычек. В DuneSQL адреса и хеши являются бинарными значениями, а не строками.

Это даст ту же информацию, что и на странице транзакций Etherscan. Для сравнения, вот два источника:

### Разбор транзакций {#breaking-down-transactions}

Отправленная транзакция включает в себя несколько элементов информации, в том числе ([источник](/developers/docs/transactions/)):

- **Получатель**: Адрес получения (запрашивается как "to")
- **Подпись**: Хотя приватные ключи отправителя подписывают транзакцию, с помощью SQL мы можем запросить публичный адрес отправителя ("from").
- **Сумма**: Это количество переведенных ETH (см. столбец `ether`).
- **Данные**: Это произвольные данные, которые были хешированы (см. столбец `data`)
- **gasLimit** – лимит газа, максимальное количество единиц газа, которое может быть потреблено транзакцией. Единицы газа представляют собой вычислительные шаги
- **maxPriorityFeePerGas** - максимальное количество газа, которое будет включено в качестве чаевых валидатору
- **maxFeePerGas** - максимальное количество газа, которое отправитель готов заплатить за транзакцию (включая baseFeePerGas и maxPriorityFeePerGas)

Мы можем запросить эти конкретные элементы информации для транзакций на публичный адрес Фонда Ethereum:

```sql
SELECT
    "to",
    "from",
    value / 1e18 AS ether,
    data,
    gas_limit,
    gas_price / 1e9 AS gas_price_gwei,
    gas_used,
    ROUND(CAST(gas_used AS DOUBLE) / gas_limit * 100, 2) AS gas_used_pct
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
```

`CAST` необходимо, поскольку деление одного целого числа на другое в DuneSQL дает целочисленный результат, что округлило бы почти каждый процент до нуля.

### Блоки {#blocks}

Каждая транзакция изменяет состояние Виртуальной машины Ethereum ([EVM](/developers/docs/evm/)) ([источник](/developers/docs/transactions/)). Транзакции транслируются в сеть для проверки и включения в блок. Каждая транзакция связана с номером блока. Чтобы увидеть данные, мы могли бы запросить конкретный номер блока: 12396854 (самый последний блок среди транзакций Фонда Ethereum на момент написания статьи, в мае 2021 года).

Более того, когда мы запрашиваем следующие два блока, мы видим, что каждый блок содержит хеш предыдущего блока (т. е. родительский хеш), иллюстрируя, как формируется блокчейн.

Каждый блок содержит ссылку на свой родительский блок. Это показано ниже между столбцами `hash` и `parent_hash` ([источник](/developers/docs/blocks/)):

![parent_hash](./parent_hash.png)

Вот запрос:

```sql
SELECT
   time,
   number,
   hash,
   parent_hash,
   nonce
FROM ethereum.blocks
WHERE number IN (12396854, 12396855, 12396856)
```

Мы можем изучить блок, запросив время, номер блока, хеш, родительский хеш и нонс. Блок 12396854 был создан до [Слияния](/roadmap/merge/), когда блоки добывались с помощью доказательства выполнения работы (PoW) и нонс имел значение. В блоках с доказательством доли владения (PoS) нонс всегда равен нулю.

Единственное, что не охватывает этот запрос, — это _список транзакций_, для которого требуется отдельный запрос ниже, и _корень состояния_. Полный или архивный узел будет хранить все транзакции и переходы состояний, позволяя клиентам запрашивать состояние цепи в любое время. Поскольку для этого требуется большой объем памяти, мы можем отделить данные цепи от данных состояния:

- Данные цепи (список блоков, транзакций)
- Данные состояния (результат перехода состояния каждой транзакции)

Корень состояния относится к последнему и является _неявными_ данными (не хранится ончейн), в то время как данные цепи являются явными и хранятся в самой цепи ([источник](https://ethereum.stackexchange.com/questions/359/where-is-the-state-data-stored)).

В этом руководстве мы сосредоточимся на ончейн-данных, которые _можно_ запросить с помощью SQL через Dune.

Как указано выше, каждый блок содержит список транзакций, мы можем запросить его, отфильтровав по конкретному блоку. Мы попробуем блок 12396854:

```sql
SELECT * FROM ethereum.transactions
WHERE block_number = 12396854
```

Вот вывод SQL в Dune:

![Screenshot of a list of Ethereum transactions](./list_of_txn.png)

Добавление этого единственного блока в цепь изменяет состояние Виртуальной машины Ethereum ([EVM](/developers/docs/evm/)). Десятки, а иногда и сотни транзакций проверяются одновременно. В данном конкретном случае было включено 222 транзакции.

Чтобы увидеть, сколько из них на самом деле были успешными, мы добавим еще один фильтр для подсчета успешных транзакций:

```sql
SELECT
    COUNT(*) AS num_successful_txn
FROM ethereum.transactions
WHERE block_number = 12396854 AND success = true
```

Для блока 12396854 из 222 транзакций 204 были успешно проверены:

![Screenshot of a successful Ethereum transaction](./successful_txn.png)

Запросы на транзакции происходят десятки раз в секунду, но блоки добавляются только периодически ([источник](/developers/docs/blocks/)). При доказательстве выполнения работы (PoW) блок добывался в среднем каждые 13–15 секунд с большими отклонениями. После [Слияния](/roadmap/merge/) в сентябре 2022 года доказательство доли владения (PoS) делит время на 12-секундные слоты, и в каждом слоте может быть не более одного блока.

Таким образом, сегодня может быть не более 86400 / 12 = 7200 блоков в день. На практике их немного меньше, потому что валидатор иногда пропускает свой слот.

График количества блоков Эфириума, создаваемых в день (2016–2021 гг.):

![Chart showing daily Ethereum block production](./daily_blocks.png)

Среднее количество блоков, создаваемых ежедневно за этот период времени, составляет ~5874:

![Chart showing daily Ethereum block production](./avg_daily_blocks.png)

Запросы:

Вот запрос для визуализации количества блоков, создаваемых ежедневно. Условие `WHERE` исключает текущий день, который еще не завершен.

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    COUNT(*) AS block_count
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

А этот запрос вычисляет среднее количество блоков, создаваемых в день, до и после Слияния. Блок 15537394 — это первый блок с доказательством доли владения.

```sql
WITH daily AS (
    SELECT
        DATE_TRUNC('day', time) AS dt,
        MIN(number) >= 15537394 AS after_merge,
        COUNT(*) AS block_count
    FROM ethereum.blocks
    WHERE time < DATE_TRUNC('day', NOW())
    GROUP BY 1
)
SELECT
    after_merge,
    AVG(block_count) AS avg_block_count,
    86400 / AVG(block_count) AS avg_seconds_per_block
FROM daily
GROUP BY 1
```

Когда это руководство было впервые написано в мае 2021 года, среднее значение составляло 5874 блока в день, или один блок каждые 14,7 секунды. После Слияния среднее значение чуть ниже максимума в 7200, около одного блок каждые 12 секунд.

### Газ {#gas}

Блоки ограничены в размере. Каждый блок имеет лимит газа, а начиная с [EIP-1559](/developers/docs/gas/#base-fee) каждый блок также имеет целевой показатель газа, который составляет половину лимита. Когда блоки используют больше газа, чем целевой показатель, базовая комиссия увеличивается, а когда меньше — уменьшается. Сам лимит газа корректируется валидаторами, и за эти годы он повышался несколько раз. Лимиты необходимы для предотвращения произвольно больших размеров блоков, создающих нагрузку на полные узлы с точки зрения дискового пространства и требований к скорости ([источник](/developers/docs/blocks/)).

Один из способов концептуализации лимита газа в блоке — рассматривать его как **предложение** доступного пространства блока, в котором можно группировать транзакции. Лимит газа в блоке можно запросить и визуализировать с 2016 года по сегодняшний день:

![Chart showing average Ethereum gas limit over time](./avg_gas_limit.png)

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    AVG(gas_limit) AS avg_block_gas_limit
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

Затем есть фактический газ, используемый ежедневно для оплаты вычислений, выполняемых в цепи Эфириума (т. е. отправка транзакции, вызов смарт-контракта, чеканка невзаимозаменяемого токена (NFT)). Это **спрос** на доступное пространство блоков Эфириума:

![Chart showing daily Ethereum gas used](./daily_gas_used.png)

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    AVG(gas_used) AS avg_block_gas_used
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

Мы также можем сопоставить эти два графика вместе, чтобы увидеть, как соотносятся **спрос и предложение**:

![gas_demand_supply](./gas_demand_supply.png)

Таким образом, мы можем понимать цены на газ как функцию спроса на пространство блоков Эфириума при наличии доступного предложения.

Наконец, мы можем захотеть запросить средние ежедневные цены на газ для цепи Эфириума, однако это приведет к особенно долгому времени выполнения запроса, поэтому мы отфильтруем наш запрос до среднего количества газа, уплаченного за транзакцию Фондом Ethereum.

![Chart showing Ethereum Foundation daily gas usage](./ef_daily_gas.png)

Мы можем видеть цены на газ, уплаченные за все транзакции, совершенные на адрес Фонда Ethereum за эти годы. Вот запрос:

```sql
SELECT
    block_time,
    gas_price / 1e9 AS gas_price_gwei,
    value / 1e18 AS eth_sent
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
```
