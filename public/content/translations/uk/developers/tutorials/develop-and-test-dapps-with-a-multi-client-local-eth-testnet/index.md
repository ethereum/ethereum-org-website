## Вступ {#introduction}

Цей посібник проведе вас через процес створення налаштовуваної локальної тестової мережі Етеріуму, розгортання в ній смарт-контракту та використання цієї тестової мережі для запуску тестів вашого децентралізованого застосунку (dapp). Цей посібник призначений для розробників dapp, які хочуть розробляти та тестувати свої застосунки локально з різними конфігураціями мережі перед розгортанням у діючій тестовій мережі або Головній мережі.

У цьому посібнику ви:

- Створите локальну тестову мережу Етеріуму за допомогою [`ethereum-package`](https://github.com/ethpandaops/ethereum-package), використовуючи [Kurtosis](https://www.kurtosis.com/),
- Підключите своє середовище розробки dapp Hardhat до локальної тестової мережі, щоб скомпілювати, розгорнути та протестувати dapp, і
- Налаштуєте локальну тестову мережу, включаючи такі параметри, як кількість вузлів і конкретні пари клієнтів рівня виконання (EL) та рівня консенсусу (CL), щоб забезпечити робочі процеси розробки та тестування для різних конфігурацій мережі.

### Що таке Kurtosis? {#what-is-kurtosis}

[Kurtosis](https://www.kurtosis.com/) — це компонована система збірки, призначена для налаштування багатоконтейнерних тестових середовищ. Зокрема, вона дозволяє розробникам створювати відтворювані середовища, які вимагають динамічної логіки налаштування, наприклад, тестові мережі блокчейну.

У цьому посібнику пакет Kurtosis `ethereum-package`, який підтримується [ethPandaOps](https://ethpandaops.io/), запускає локальну тестову мережу Етеріуму. Він підтримує всі основні клієнти рівня виконання (EL), такі як [`geth`](https://geth.ethereum.org/), та клієнти рівня консенсусу (CL), такі як [`teku`](https://consensys.io/teku), [`lighthouse`](https://lighthouse.sigmaprime.io/) і [`lodestar`](https://lodestar.chainsafe.io/). Цей пакет слугує налаштовуваною та компонованою альтернативою мережам у таких фреймворках, як Hardhat Network та Anvil. Kurtosis пропонує розробникам більший контроль і гнучкість над тестовими мережами, які вони використовують, що є головною причиною, чому команди клієнтів Етеріуму використовують його для тестування оновлень мережі.

## Налаштування Kurtosis {#setting-up-kurtosis}

Перш ніж продовжити, переконайтеся, що ви:

- [Встановили та запустили рушій Docker](https://docs.kurtosis.com/install/#i-install--start-docker) на вашій локальній машині
- [Встановили Kurtosis CLI](https://docs.kurtosis.com/install#ii-install-the-cli) (або оновили його до останньої версії, якщо CLI вже встановлено)
- Встановили [Node.js](https://nodejs.org/en) (для вашого середовища dapp)

## Створення локальної тестової мережі Етеріуму {#instantiate-testnet}

Щоб запустити локальну тестову мережу Етеріуму, виконайте:

```sh
kurtosis run --enclave local-eth-testnet github.com/ethpandaops/ethereum-package
```

Примітка: Ця команда називає вашу мережу «local-eth-testnet» за допомогою прапорця `--enclave`.

Kurtosis виводитиме кроки, які він виконує внутрішньо, під час інтерпретації, перевірки та виконання інструкцій. Наприкінці він виведе підсумок створеного анклаву. Підсумок включає список **файлових артефактів** та список **служб користувача**. За замовчуванням служби користувача включають один вузол:

- `el-1-geth-lighthouse`, клієнт виконання `geth`
- `cl-1-lighthouse-geth`, маяковий вузол `lighthouse`
- `vc-1-geth-lighthouse`, клієнт валідатора `lighthouse`

Кожна служба вказана з портами, які вона відкриває, і локальним портом, на який кожен з них відображається. Наприклад, порт `rpc` служби `el-1-geth-lighthouse` — це кінцева точка JSON-RPC, яку використовуватимуть ваші інструменти dapp. Точні служби та номери портів на вашій машині відрізнятимуться.

Ви можете переглянути цей підсумок знову в будь-який час, виконавши:

```sh
kurtosis enclave inspect local-eth-testnet
```

Вітаємо! Ви використали Kurtosis для створення локальної тестової мережі Етеріуму з клієнтом рівня консенсусу (`lighthouse`) та клієнтом рівня виконання (`geth`) через Docker.

### Огляд {#review-instantiate-testnet}

У цьому розділі ви виконали команду, яка вказала Kurtosis використати пакет [`ethereum-package`, розміщений віддалено на GitHub](https://github.com/ethpandaops/ethereum-package), щоб запустити локальну тестову мережу Етеріуму в межах [анклаву](https://docs.kurtosis.com/advanced-concepts/enclaves/) Kurtosis. Усередині вашого анклаву ви знайдете як «файлові артефакти», так і «служби користувача».

[Файлові артефакти](https://docs.kurtosis.com/advanced-concepts/files-artifacts/) у вашому анклаві включають усі дані, згенеровані та використані для початкового завантаження клієнтів EL та CL, такі як файли генезису та ключі валідатора. Дані генезису були створені за допомогою [ethereum-genesis-generator](https://github.com/ethpandaops/ethereum-genesis-generator).

Служби користувача відображають усі контейнеризовані служби, що працюють у вашому анклаві. Ви помітите, що було створено один вузол, який містить як клієнт EL, так і клієнт CL.

## Підключення середовища розробки dapp до локальної тестової мережі Етеріуму {#connect-your-dapp}

### Налаштування середовища розробки dapp {#set-up-dapp-env}

Тепер, коли у вас є запущена локальна тестова мережа, ви можете підключити своє середовище розробки децентралізованого застосунку (dapp) для її використання. У цьому посібнику використовуватиметься фреймворк Hardhat для розгортання dapp для гри в блекджек у вашій локальній тестовій мережі.

Щоб налаштувати середовище розробки dapp, клонуйте репозиторій, який містить наш зразок dapp, і встановіть його залежності, виконавши:

```sh
git clone https://github.com/kurtosis-tech/awesome-kurtosis.git
cd awesome-kurtosis/smart-contract-example
npm install --legacy-peer-deps
```

Прапорець `--legacy-peer-deps` потрібен, оскільки деякі плагіни Hardhat у зразку проєкту оголошують конфліктні версії однорангових залежностей.

Папка [smart-contract-example](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example), яка тут використовується, містить типове налаштування для розробника dapp, що використовує фреймворк [Hardhat](https://hardhat.org/):

- [`contracts/`](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example/contracts) містить кілька простих смарт-контрактів для dapp блекджеку
- [`scripts/`](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example/scripts) містить скрипт для розгортання контракту токена у вашій локальній мережі Етеріуму
- [`test/`](https://github.com/kurtosis-tech/awesome-kurtosis/tree/main/smart-contract-example/test) містить простий тест .js для вашого контракту токена, щоб підтвердити, що для кожного гравця в нашому dapp блекджеку випущено 1000 токенів
- [`hardhat.config.ts`](https://github.com/kurtosis-tech/awesome-kurtosis/blob/main/smart-contract-example/hardhat.config.ts) налаштовує вашу конфігурацію Hardhat

### Налаштування Hardhat для використання локальної тестової мережі {#configure-hardhat}

Після налаштування середовища розробки dapp ви підключите Hardhat для використання локальної тестової мережі Етеріуму, згенерованої за допомогою Kurtosis. Спочатку знайдіть локальну адресу кінцевої точки JSON-RPC клієнта виконання:

```sh
kurtosis port print local-eth-testnet el-1-geth-lighthouse rpc
```

Результатом буде URL-адреса, наприклад `http://127.0.0.1:32769`. Ваш порт відрізнятиметься. Замініть `<PORT>` у структурі `localnet` у вашому файлі конфігурації `hardhat.config.ts` на цей порт.

Приклад у `hardhat.config.ts`:

```js
localnet: {
  url: 'http://127.0.0.1:<PORT>',//TODO: ЗАМІНІТЬ <PORT> НА ПОРТ URI ВУЗЛА, СТВОРЕНОГО ПАКЕТОМ KURTOSIS МЕРЕЖІ ETH
  // Це приватні ключі, пов'язані з попередньо профінансованими тестовими обліковими записами, створеними пакетом eth-network-package
  //https://github.com/ethpandaops/ethereum-package/blob/main/src/prelaunch_data_generator/genesis_constants/genesis_constants.star
  accounts: [
    "bcdf20249abf0ed6d944c0288fad489e33f66b3960d9e6229c1cd214ed3bbe31",
    "53321db7c1e331d93a11a41d16f004d7ff63972ec8ec7c25db329728ceeb1710",
    "ab63b23eb7941c1251757e24b3d2350d2bc05c3c388d06f8fe6feafefb1e8c70",
    "5d2344259f42259f82d2c140aa66102ba89b57b4883ee441a8b312622bd42491",
    "27515f805127bebad2fb9b183508bdacb8c763da16f54e0678b16e8f28ef3fff",
    "7ff1a4c1d57e5e784d327c4c7651e952350bc271f156afb3d00d20f5ef924856",
  ],
},
```

Ці приватні ключі є загальновідомими тестовими ключами. Ніколи не використовуйте їх у Головній мережі або будь-якій публічній мережі.

Після збереження файлу ваше середовище розробки dapp Hardhat буде підключено до локальної тестової мережі Етеріуму! Ви можете перевірити, чи працює ваша тестова мережа, виконавши:

```sh
npx hardhat balances --network localnet
```

У виводі вказано адресу та баланс кожного з наведених вище акаунтів. Наприклад, перший рядок має виглядати так:

```
0x8943545177806ED17B9F23F0a21ee5948eCaa776 has balance <a large balance>
```

Це підтверджує, що Hardhat використовує вашу локальну тестову мережу та виявляє попередньо поповнені акаунти, створені пакетом `ethereum-package`.

### Розгортання та тестування вашого dapp локально {#deploy-and-test-dapp}

Коли середовище розробки dapp повністю підключено до локальної тестової мережі Етеріуму, ви можете запускати робочі процеси розробки та тестування для вашого dapp, використовуючи локальну тестову мережу.

Щоб скомпілювати та розгорнути смарт-контракт `ChipToken.sol` для локального прототипування та розробки, виконайте:

```sh
npx hardhat compile
npx hardhat run scripts/deploy.ts --network localnet
```

Вивід має виглядати приблизно так:

```
ChipToken deployed to: 0xAb2A01BC351770D09611Ac80f1DE076D56E0487d
```

Тепер спробуйте запустити тест `ChipToken.js` для вашого локального dapp, щоб підтвердити, що для кожного гравця в нашому dapp блекджеку випущено 1000 токенів. Зразок тесту все ще використовує функцію `deployed()` з ethers v5, яку в ethers v6 замінено на `waitForDeployment()`, тому спочатку оновіть її:

```sh
sed -i.bak 's/\.deployed()/.waitForDeployment()/' test/ChipToken.js
```

Потім запустіть тест:

```sh
npx hardhat test --network localnet
```

Вивід має виглядати приблизно так:

```
ChipToken
    mint
      ✔ should mint 1000 chips for PLAYER ONE

  1 passing (654ms)
```

### Огляд {#review-dapp-workflows}

На цьому етапі ви налаштували середовище розробки dapp, підключили його до локальної мережі Етеріуму, створеної Kurtosis, а також скомпілювали, розгорнули та запустили простий тест для вашого dapp.

Тепер давайте розглянемо, як можна налаштувати базову мережу для тестування наших dapp за різних конфігурацій мережі.

## Налаштування локальної тестової мережі Етеріуму {#configure-testnet}

### Зміна конфігурацій клієнтів та кількості вузлів {#configure-client-config-and-num-nodes}

Вашу локальну тестову мережу Етеріуму можна налаштувати на використання різних пар клієнтів EL та CL, а також різної кількості вузлів, залежно від сценарію та конкретної конфігурації мережі, яку ви хочете розробити або протестувати. Це означає, що після налаштування ви можете запустити кастомізовану локальну тестову мережу та використовувати її для виконання тих самих робочих процесів (розгортання, тести тощо) за різних конфігурацій мережі, щоб переконатися, що все працює належним чином. Щоб дізнатися більше про інші параметри, які можна змінити, перегляньте [документацію з конфігурації `ethereum-package`](https://github.com/ethpandaops/ethereum-package#configuration).

Спробуйте! Ви можете передати різні параметри конфігурації до `ethereum-package` через файл YAML. Цей файл параметрів мережі містить конкретні конфігурації, які Kurtosis використовуватиме для налаштування локальної мережі Етеріуму.

Створіть файл із назвою `network_params.yaml`, який запускає три вузли з різними парами EL/CL:

- Вузол 1 з `geth`/`lighthouse`
- Вузол 2 з `geth`/`lodestar`
- Вузол 3 з `geth`/`teku`

Ця конфігурація створює гетерогенну мережу реалізацій вузлів Етеріуму для тестування вашого dapp. Ваш файл конфігурації має виглядати так:

```yaml
participants:
  - el_type: geth
    cl_type: lighthouse
  - el_type: geth
    cl_type: lodestar
  - el_type: geth
    cl_type: teku
network_params:
  seconds_per_slot: 12
```

Кожен запис у `participants` відповідає вузлу в мережі, тому 3 записи `participants` вкажуть Kurtosis запустити 3 вузли у вашій мережі. Кожен запис дозволяє вказати пару EL та CL, яка використовується для цього конкретного вузла. Будь-які параметри, які ви не вкажете, зберігають свої значення за замовчуванням.

Структура `network_params` налаштовує параметри мережі, які використовуються для створення файлів генезису для кожного вузла, а також інші параметри, такі як кількість секунд на слот мережі.

Збережіть файл параметрів, а потім використайте його для запуску вашого пакета Kurtosis, виконавши:

```sh
kurtosis clean -a && kurtosis run --enclave local-eth-testnet github.com/ethpandaops/ethereum-package --args-file ./network_params.yaml
```

Примітка: команда `kurtosis clean -a` використовується тут, щоб дати вказівку Kurtosis знищити стару тестову мережу та її вміст перед запуском нової.

Знову ж таки, Kurtosis попрацює деякий час і виведе окремі кроки, які виконуються. Зрештою, він виведе підсумок анклаву. Цього разу служби користувача включають три вузли, наприклад `el-1-geth-lighthouse`, `el-2-geth-lodestar` та `el-3-geth-teku` для клієнтів виконання, разом із відповідними клієнтами консенсусу та валідатора.

Вітаємо! Ви успішно налаштували свою локальну тестову мережу на 3 вузли замість 1. Щоб запустити ті самі робочі процеси для вашого dapp, що й раніше (розгортання та тестування), виконайте ті самі операції, замінивши `<PORT>` у структурі `localnet` у вашому файлі конфігурації `hardhat.config.ts` на порт `rpc` будь-якої служби `el-<num>-...` у вашій новій локальній тестовій мережі з 3 вузлами.

Ми рекомендуємо вам ознайомитися з нашим [коротким посібником](https://docs.kurtosis.com/quickstart) та іншими прикладами в нашому [репозиторії awesome-kurtosis](https://github.com/kurtosis-tech/awesome-kurtosis).

Пакет `ethereum-package` також може запускати додаткові служби разом із вашою мережею, такі як спамер транзакцій (для імітації транзакцій), оглядач блоків, а також підключені екземпляри Grafana та Prometheus. Щоб увімкнути їх, перелічіть їх у розділі `additional_services` у вашому файлі параметрів, як описано в [документації пакета](https://github.com/ethpandaops/ethereum-package#configuration).
