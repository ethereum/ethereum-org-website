Багато посібників з Етеріуму орієнтовані на розробників, але бракує освітніх ресурсів для аналітиків даних або людей, які хочуть переглядати ончейн-дані без запуску клієнта чи вузла.

Цей посібник допомагає читачам зрозуміти фундаментальні концепції Етеріуму, зокрема транзакції, блоки та газ, шляхом запитів до ончейн-даних за допомогою мови структурованих запитів (SQL) через інтерфейс, який надає [Dune](https://dune.com/). У запитах використовується [DuneSQL](https://docs.dune.com/query-engine/overview), діалект SQL від Dune.

Ончейн-дані можуть допомогти нам зрозуміти Етеріум, мережу та економіку обчислювальних потужностей, а також мають слугувати основою для розуміння викликів, з якими сьогодні стикається Етеріум (наприклад, зростання цін на газ), і, що важливіше, дискусій навколо рішень для масштабування.

### Транзакції {#transactions}

Шлях користувача в Етеріумі починається з ініціалізації контрольованого користувачем акаунта або сутності з балансом ETH. Існує два типи акаунтів: контрольовані користувачем або смарт-контракти (див. [ethereum.org](/developers/docs/accounts/)).

Будь-який акаунт можна переглянути в оглядачі блоків, як-от [Etherscan](https://etherscan.io/) або [Blockscout](https://eth.blockscout.com/). Оглядачі блоків — це портал до даних Етеріуму. Вони в режимі реального часу відображають дані про блоки, транзакції, валідаторів, акаунти та іншу ончейн-активність (див. [тут](/developers/docs/data-and-analytics/block-explorers/)).

Однак користувач може захотіти зробити запит до даних безпосередньо, щоб звірити інформацію, надану зовнішніми оглядачами блоків. [Dune](https://dune.com/) надає таку можливість будь-кому, хто має певні знання SQL.

Для довідки, акаунт смарт-контракту Фундації Ethereum (EF) можна переглянути на [Blockscout](https://eth.blockscout.com/address/0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe).

Варто зазначити, що всі акаунти, включно з акаунтом EF, мають публічну адресу, яку можна використовувати для надсилання та отримання транзакцій.

Баланс акаунта на Etherscan складається зі звичайних та внутрішніх транзакцій. Внутрішні транзакції, незважаючи на назву, не є _справжніми_ транзакціями, які змінюють стан ланцюга. Це перекази цінності, ініційовані виконанням контракту ([джерело](https://ethereum.stackexchange.com/questions/3417/how-to-get-contract-internal-transactions)). Оскільки внутрішні транзакції не мають підпису, вони **не** включаються до блокчейну як транзакції. Dune записує їх окремо, у таблиці `ethereum.traces`.

Тому цей посібник буде зосереджений на звичайних транзакціях. Запит до них можна зробити так:

```sql
WITH temp_table AS (
SELECT
    hash,
    block_number,
    block_time,
    "from",
    "to",
    value / 1e18 AS ether,
    gas_used,
    gas_price / 1e9 AS gas_price_gwei
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
)
SELECT
    hash,
    block_number,
    block_time,
    "from",
    "to",
    ether,
    (gas_used * gas_price_gwei) / 1e9 AS txn_fee
FROM temp_table
```

Зверніть увагу, що адреси записуються як літерали `0x...` без лапок. У DuneSQL адреси та хеші є бінарними значеннями, а не рядками.

Це дасть ту саму інформацію, що й на сторінці транзакцій Etherscan. Для порівняння, ось два джерела:

### Розбір транзакцій {#breaking-down-transactions}

Надіслана транзакція містить кілька частин інформації, зокрема ([джерело](/developers/docs/transactions/)):

- **Одержувач (Recipient)**: Адреса отримання (у запиті як «to»).
- **Підпис (Signature)**: Хоча приватні ключі відправника підписують транзакцію, за допомогою SQL ми можемо зробити запит на публічну адресу відправника («from»).
- **Значення (Value)**: Це сума переказаних ETH (див. стовпець `ether`).
- **Дані (Data)**: Це довільні дані, які були захешовані (див. стовпець `data`).
- **gasLimit** — ліміт газу, максимальна кількість одиниць газу, яка може бути спожита транзакцією. Одиниці газу представляють обчислювальні кроки.
- **maxPriorityFeePerGas** — максимальна кількість газу, яка буде включена як пріоритетна комісія для валідатора.
- **maxFeePerGas** — максимальна кількість газу, яку готові заплатити за транзакцію (включно з baseFeePerGas та maxPriorityFeePerGas).

Ми можемо зробити запит на ці конкретні частини інформації для транзакцій на публічну адресу Фундації Ethereum:

```sql
SELECT
    "to",
    "from",
    value / 1e18 AS ether,
    data,
    gas_limit,
    gas_price / 1e9 AS gas_price_gwei,
    gas_used,
    ROUND(CAST(gas_used AS DOUBLE) / gas_limit * 100, 2) AS gas_used_pct
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
```

`CAST` є необхідним, оскільки ділення одного цілого числа на інше в DuneSQL дає цілочисельний результат, що округлило б майже кожен відсоток до нуля.

### Блоки {#blocks}

Кожна транзакція змінюватиме стан Віртуальної машини Ethereum ([EVM](/developers/docs/evm/)) ([джерело](/developers/docs/transactions/)). Транзакції транслюються в мережу для перевірки та включення в блок. Кожна транзакція пов'язана з номером блоку. Щоб побачити дані, ми можемо зробити запит на конкретний номер блоку: 12396854 (останній блок серед транзакцій Фундації Ethereum на момент написання статті, у травні 2021 року).

Крім того, коли ми робимо запит на наступні два блоки, ми бачимо, що кожен блок містить хеш попереднього блоку (тобто батьківський хеш), що ілюструє, як формується блокчейн.

Кожен блок містить посилання на свій батьківський блок. Це показано нижче між стовпцями `hash` та `parent_hash` ([джерело](/developers/docs/blocks/)):

![parent_hash](./parent_hash.png)

Ось запит:

```sql
SELECT
   time,
   number,
   hash,
   parent_hash,
   nonce
FROM ethereum.blocks
WHERE number IN (12396854, 12396855, 12396856)
```

Ми можемо дослідити блок, зробивши запит на час, номер блоку, хеш, батьківський хеш та нонс. Блок 12396854 був створений до [Злиття](/roadmap/merge/), коли блоки добувалися за допомогою доказу виконання роботи (PoW), і нонс мав значення. У блоках з доказом частки (PoS) нонс завжди дорівнює нулю.

Єдине, що не охоплює цей запит, — це _список транзакцій_, який вимагає окремого запиту нижче, та _корінь стану_ (state root). Повний або архівний вузол зберігатиме всі транзакції та переходи станів, дозволяючи клієнтам робити запити щодо стану ланцюга в будь-який час. Оскільки це вимагає великого обсягу пам'яті, ми можемо відокремити дані ланцюга від даних стану:

- Дані ланцюга (список блоків, транзакцій)
- Дані стану (результат переходу стану кожної транзакції)

Корінь стану належить до останніх і є _неявними_ даними (не зберігаються ончейн), тоді як дані ланцюга є явними і зберігаються в самому ланцюзі ([джерело](https://ethereum.stackexchange.com/questions/359/where-is-the-state-data-stored)).

У цьому посібнику ми зосередимося на ончейн-даних, до яких _можна_ робити запити за допомогою SQL через Dune.

Як зазначалося вище, кожен блок містить список транзакцій, ми можемо зробити запит на це, відфільтрувавши за певним блоком. Спробуємо блок 12396854:

```sql
SELECT * FROM ethereum.transactions
WHERE block_number = 12396854
```

Ось результат SQL у Dune:

![Screenshot of a list of Ethereum transactions](./list_of_txn.png)

Додавання цього єдиного блоку до ланцюга змінює стан Віртуальної машини Ethereum ([EVM](/developers/docs/evm/)). Десятки, а іноді й сотні транзакцій перевіряються одночасно. У цьому конкретному випадку було включено 222 транзакції.

Щоб побачити, скільки з них насправді були успішними, ми додамо ще один фільтр для підрахунку успішних транзакцій:

```sql
SELECT
    COUNT(*) AS num_successful_txn
FROM ethereum.transactions
WHERE block_number = 12396854 AND success = true
```

Для блоку 12396854 із 222 загальних транзакцій 204 були успішно перевірені:

![Screenshot of a successful Ethereum transaction](./successful_txn.png)

Запити на транзакції відбуваються десятки разів на секунду, але блоки додаються лише періодично ([джерело](/developers/docs/blocks/)). За умови доказу виконання роботи (PoW) блок добувався в середньому кожні 13–15 секунд із великими варіаціями. Після [Злиття](/roadmap/merge/) у вересні 2022 року доказ частки (PoS) ділить час на 12-секундні слоти, і кожен слот може мати щонайбільше один блок.

Отже, сьогодні може бути щонайбільше 86400 / 12 = 7200 блоків на день. На практиці їх трохи менше, оскільки валідатор іноді пропускає свій слот.

Графік кількості видобутих блоків Етеріуму за день (2016–2021 рр.):

![Chart showing daily Ethereum block production](./daily_blocks.png)

Середня кількість блоків, що видобувалися щодня за цей період, становить ~5874:

![Chart showing daily Ethereum block production](./avg_daily_blocks.png)

Запити:

Ось запит для візуалізації кількості блоків, що видобуваються щодня. Умова `WHERE` виключає поточний день, який ще не завершився.

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    COUNT(*) AS block_count
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

А цей запит обчислює середню кількість блоків, що видобуваються за день, до та після Злиття. Блок 15537394 є першим блоком із доказом частки (PoS).

```sql
WITH daily AS (
    SELECT
        DATE_TRUNC('day', time) AS dt,
        MIN(number) >= 15537394 AS after_merge,
        COUNT(*) AS block_count
    FROM ethereum.blocks
    WHERE time < DATE_TRUNC('day', NOW())
    GROUP BY 1
)
SELECT
    after_merge,
    AVG(block_count) AS avg_block_count,
    86400 / AVG(block_count) AS avg_seconds_per_block
FROM daily
GROUP BY 1
```

Коли цей посібник був уперше написаний у травні 2021 року, середній показник становив 5874 блоки на день, або один блок кожні 14,7 секунди. Після Злиття середній показник трохи нижчий за максимум у 7200, приблизно один блок кожні 12 секунд.

### Газ {#gas}

Блоки обмежені за розміром. Кожен блок має ліміт газу, а починаючи з [EIP-1559](/developers/docs/gas/#base-fee), кожен блок також має цільовий показник газу, який становить половину ліміту. Коли блоки використовують більше газу, ніж цільовий показник, базова комісія зростає, а коли менше — знижується. Сам ліміт газу коригується валідаторами, і з роками він кілька разів підвищувався. Ліміти необхідні для того, щоб запобігти довільно великим розмірам блоків, які створюють навантаження на повні вузли з точки зору дискового простору та вимог до швидкості ([джерело](/developers/docs/blocks/)).

Один зі способів концептуалізації ліміту газу в блоці — розглядати його як **пропозицію** доступного простору блоку, у якому можна групувати транзакції. Ліміт газу в блоці можна запитати та візуалізувати з 2016 року до сьогодні:

![Chart showing average Ethereum gas limit over time](./avg_gas_limit.png)

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    AVG(gas_limit) AS avg_block_gas_limit
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

Також є фактичний газ, який щодня використовується для оплати обчислень, що виконуються в ланцюзі Етеріуму (тобто надсилання транзакції, виклик смарт-контракту, карбування NFT). Це **попит** на доступний простір блоку Етеріуму:

![Chart showing daily Ethereum gas used](./daily_gas_used.png)

```sql
SELECT
    DATE_TRUNC('day', time) AS dt,
    AVG(gas_used) AS avg_block_gas_used
FROM ethereum.blocks
WHERE time < DATE_TRUNC('day', NOW())
GROUP BY 1
ORDER BY 1
```

Ми також можемо зіставити ці два графіки разом, щоб побачити, як співвідносяться **попит і пропозиція**:

![gas_demand_supply](./gas_demand_supply.png)

Тому ми можемо розуміти ціни на газ як функцію попиту на простір блоку Етеріуму з огляду на наявну пропозицію.

Нарешті, ми можемо захотіти зробити запит на середні щоденні ціни на газ для ланцюга Етеріуму, однак це призведе до надто тривалого часу виконання запиту, тому ми відфільтруємо наш запит до середньої кількості газу, сплаченої за транзакцію Фундацією Ethereum.

![Chart showing Ethereum Foundation daily gas usage](./ef_daily_gas.png)

Ми можемо побачити ціни на газ, сплачені за всі транзакції, здійснені на адресу Фундації Ethereum протягом багатьох років. Ось запит:

```sql
SELECT
    block_time,
    gas_price / 1e9 AS gas_price_gwei,
    value / 1e18 AS eth_sent
FROM ethereum.transactions
WHERE "to" = 0xde0B295669a9FD93d5F28D9Ec85E40f4cb697BAe
ORDER BY block_time DESC
```
